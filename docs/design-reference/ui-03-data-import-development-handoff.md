# 03 数据导入 UI 开发 Handoff

日期：2026-07-04

## 1. 目的

本文件把 `03 数据导入` 的 Figma 真实界面转成开发可执行边界。

本轮交付的重点不是继续解释数据导入逻辑，而是给 WinUI 实现提供可对照的真实界面、弹窗、状态页和验收门槛。

## 2. 交付关系

```text
模块功能设计文档 -> 真实 UI 图 -> 开发 handoff -> WinUI 实现 -> 本地 QA / 截图验收
```

对应关系：

- 功能逻辑：见 `docs/workbench-functional-design-spec.md` 和 `docs/figma-interface-03-data-import-review.md`。
- 真实 UI 图：见本文第 4 节的 Figma 节点。
- 实现边界：以本文第 5-9 节为准。

`03B 数据导入-状态与入口闭环` 是内部说明/检查图，不是用户会看到的产品页面，也不应该直接照着实现为一个产品页面。

## 3. 页面职责

`数据导入` 页只回答四个问题：

1. 当前有没有选择导入文件。
2. 文件是否能解析、字段是否能映射、单位是否可信。
3. 当前预检结论是否允许提交。
4. 提交后下一步是否进入 `数据检查`。

默认页面不展示：

- runner / registry / draft package
- 长日志、stdout、stderr
- 内部路径、调试 JSON
- 方法实验室结果
- 与导入无关的项目资源文件树

## 5. 实现对象和落点

页面落点：

- WinUI 页面：`OffshoreGeotechWorkbench/Pages/DataImportPage.xaml`
- 页面逻辑：`OffshoreGeotechWorkbench/Pages/DataImportPage.xaml.cs`
- 导入预览服务：沿用现有 preview/import service，不重写导入算法。

新增或重排的 UI 落点：

| 入口 | 目标落点 | 实现要求 |
| --- | --- | --- |
| `选择文件` | 系统文件选择器 + 当前页面草稿刷新 | 选中文件后显示文件数、字段映射、预览和预检摘要。 |
| `批量导入` | 同一导入草稿列表 | 一次选择多个文件；每个文件有解析状态。 |
| `设置` | `导入设置` 弹窗 | 修改文件格式、编码、分隔符、单位策略、深度列后重新预检。 |
| `智能映射` | `智能映射候选` 面板 | 只提供候选，不自动提交；低置信度必须复核。 |
| `查看详细报告` | `预检详细报告` 面板 | 能定位到问题、文件、行、列；不展示长日志。 |
| `清空草稿...` | 二次确认弹窗 | 只清空导入草稿，不删除正式数据库记录。 |
| `提交导入` | 当前页面动作 + 成功/失败状态 | 只有预检总判定可提交时可用；成功后引导进入 `数据检查`。 |

## 6. 状态规则

| 状态 | 主视觉 | 右侧属性 | 底部面板 | 按钮规则 |
| --- | --- | --- | --- | --- |
| 无文件 | 中央空状态 + `选择文件` | 文件数 0，预检未运行 | 空问题表 | `提交导入` 不出现或禁用 |
| 解析中 | 进度条 + 文件解析队列 | 当前文件、进度、提交禁用原因 | 解析提示 | `提交导入` 禁用，允许取消解析 |
| 预检警告 | 文件、映射、预览可见 | `警告，可提交` | 警告列表 | `提交导入` 可用 |
| 预检阻塞 | 阻塞摘要 + 修复入口 | `阻塞，不可提交` | 阻塞问题列表 | `提交导入` 禁用 |
| 提交成功 | 已提交摘要 + 下一步 | 写入点位、记录数、下一步 | 成功记录 | 主按钮为 `进入数据检查` |
| 写入失败 | 失败原因 + 保留草稿 | 草稿已保留、错误代码、下一步 | 数据库/写入问题 | `重试写入` 和 `导出问题` 可用 |

## 7. 布局规则

必须继承 `01 Workbench shell`：

- 顶部菜单/命令区、Activity Bar、Explorer、Editor Tabs、右侧属性面板、底部面板、状态栏的尺寸和密度不得重新自由发挥。
- `数据导入` 的业务内容只替换中央 Editor、右侧属性内容和底部问题内容。
- 底部默认页签固定为 `问题 / 预检 / 提交记录`。
- 默认不得出现 `终端`、长 `日志`、内部 `输出` 页签。
- 右侧属性面板只放当前导入批次、预检结论、下一步动作，不放实现路径和内部对象。

## 8. 中文 UI 和文案

用户可见文案必须中文。

允许保留的技术词：

- `CPT`
- `CPTU`
- `CSV`
- `Excel`
- `UTF-8`
- `SQLite`
- 字段名：`qc`、`fs`、`u2`
- 单位：`MPa`、`kPa`、`m`

禁止默认出现：

- `ready`
- `Open Project Folder`
- `Project Settings`
- `runner`
- `registry`
- `draft package`
- `fixture`
- `local QA`

## 9. 开发验收门槛

实现后至少检查：

1. Explorer 点击 `数据导入` 能打开或激活对应 Tab。
2. 无文件、解析中、预检阻塞、提交成功、写入失败五个状态都可截图验证。
3. 预检阻塞时 `提交导入` 不可用。
4. 预检警告但可提交时，右侧必须明确显示 `警告，可提交`。
5. `清空草稿...` 需要二次确认，且不删除正式数据。
6. 默认底部面板不出现 `终端` 或长日志页签。
7. 1920 x 1080 / 125% 缩放下无文字重叠、裁切、状态列挤压。
8. 截图必须显示完整工作台壳体，而不是局部裁剪。

建议验收命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\local-qa\run-local-quality-gate.ps1 -CaptureScreen
```

如果只做 Figma 或文档 handoff，不要求运行 WinUI QA；但进入 WinUI 实现后必须跑本地 QA 或记录明确的阻塞原因。
