# OffshoreGeotechWorkbench 全套功能与页面设计说明

更新时间：2026-07-03
状态：v0.2 设计说明草案，已合入第一轮多视角挑刺反馈
产品：`SIGS-OGLab | 海上风电岩土勘察解译`
应用：`OffshoreGeotechWorkbench`

## 0. 文档目的

这份文档要解决一个问题：设计师在没有历史上下文的情况下，也能清楚知道这个软件要做什么、有哪些页面、每页应该放什么、每个区域如何交互、哪些功能已经存在、哪些只是拟做、哪些不应该出现在默认界面。

设计师拿到本文档后，应能完成一套 VSCode-like 工程软件设计稿，而不是只画一个好看的壳。每个页面都要服务两个核心工作：

- 地层分层：让工程/科研人员看到 CPT/CPTU 点位的分层方案、土类、边界、证据和可采纳状态。
- 参数解译：基于已选择的分层方案，配置并运行参数方法，得到可视化曲线、层内统计和可输出的参数方案。

本文档优先定义功能、信息架构、页面内容、交互逻辑和验收标准。具体像素值可以在 Figma 里进一步细化，但不能改变本文档定义的主流程和页面职责。

## 1. 一句话产品定义

这是一个面向海上风电岩土勘察的本地桌面工作台，用于导入 CPT/CPTU 数据、检查数据质量、生成和比较地层分层方案、基于分层方案进行参数解译，并输出可追溯的工程成果包。

## 2. 当前必须锁定的设计方向

界面方向固定为：

```text
VSCode-like 工程工作台
```

这里的 VSCode-like 不是自由发挥的“深色科技感”，而是指一套明确的工作台结构：

- 顶部：菜单栏、命令区、窗口控制区。
- 左侧：深色 Activity Bar。
- 左栏：浅色 Explorer 工程树。
- 中央：Editor Tabs 和文档工作区。
- 右侧：对象属性/详情 Side Panel。
- 底部：问题、日志、预检、对比等 Bottom Panel。
- 最底：蓝色 Status Bar。

固定基础色：

| 名称 | Hex | 用途 |
| --- | --- | --- |
| VSCodeActivityBar | `#333333` | 左侧 Activity Bar |
| VSCodeTitleBar | `#DDDDDD` | 顶部标题/菜单栏 |
| VSCodeSideBar | `#F3F3F3` | Explorer 背景 |
| VSCodeEditor | `#FFFFFF` | 中央编辑区 |
| VSCodeLine | `#E5E5E5` | 分隔线、边框 |
| VSCodeAccent | `#007ACC` | 选中态、状态栏、关键焦点 |

语义色只用于状态，不作为主题强调色：

- 成功/已完成：绿色。
- 警告/待处理：橙色。
- 阻塞/错误：红色。
- 未开始/无数据：中性色，但要贴近 VSCode-like 的浅灰体系。

禁止方向：

- 不做营销式 landing page。
- 不做大圆角卡片堆叠。
- 不做紫蓝渐变、奶油底色、装饰性插画。
- 不把方法调试页当主页面。
- 不在默认工程界面暴露 runner、registry、draft package、stdout、stderr、JSON、内部路径、开发日志。

### 2.1 VSCode-like 尺寸和密度基线

为避免设计稿被画成普通后台系统，第一版 Figma 和 WinUI 实现按下列基线控制。具体数值可随窗口自适应，但相对层级不能变。

| 区域 | 基线尺寸 | 规则 |
| --- | --- | --- |
| Activity Bar | 48-52 px 宽 | 深色竖栏，只放全局图标入口 |
| Explorer | 280-340 px 宽 | 浅色树，行高 24-28 px，状态标签右对齐 |
| Editor Tab Row | 35-40 px 高 | Tab 紧凑排列，不做大卡片 |
| Top Menu/Title | 34-40 px 高 | 菜单、导航、工程标题在同一紧凑层 |
| Right Side Panel | 300-360 px 宽 | 属性详情，不放长日志 |
| Bottom Panel | 默认 160-220 px 高 | 默认收起或低高度，用户展开后可到 35% 高度 |
| Status Bar | 22-26 px 高 | 蓝底白字，短状态 |
| 主工作区内边距 | 12-16 px | 图表页可更紧，但不能贴边压字 |
| 表格/树行 | 24-30 px 高 | 工程软件密度，不做 44 px 以上的大行距 |
| 按钮高度 | 28-32 px | 工具栏按钮紧凑，主按钮可略宽但不变成营销按钮 |

默认字体层级：

| 用途 | 字号建议 | 说明 |
| --- | --- | --- |
| 顶部菜单/树节点/表格正文 | 13-14 px | 默认正文 |
| 页面小标题 | 16-18 px | 页面区域标题 |
| 关键数值 | 16-20 px | 只用于状态摘要，不做大屏数字 |
| 状态栏 | 12-13 px | 短文本 |

如果设计稿看起来像“左侧导航 + 卡片 Dashboard”，说明没有通过 VSCode-like 基线。

## 3. 用户与核心场景

### 3.1 核心用户

| 用户 | 关注点 | 设计上的要求 |
| --- | --- | --- |
| 工程人员 | 数据能不能用，分层和参数是否可采纳，成果是否可输出 | 默认页先给结论、状态和阻塞项，少解释，路径短 |
| 科研人员 | 不同方法的结果如何比较，证据和算法来源是什么 | 可进入对比、证据、方法详情，但不干扰默认页 |
| 内部开发/方法维护者 | 方法能否接入，输入输出是否正确，日志是什么 | 放在方法实验室，不进入默认工程消费页 |

### 3.2 核心任务

用户打开软件后，应该能沿着下面的路径完成一次完整工作：

```text
打开/新建工程
  -> 选择点位
  -> 导入 CPT/CPTU 数据
  -> 检查数据
  -> 生成或选择地层分层方案
  -> 采纳分层方案
  -> 选择参数解译方法
  -> 运行参数解译
  -> 采纳参数方案
  -> 成果输出
```

| 研究模式 | 高级/科研 | 高级入口，默认不抢主流程 | 多方法试算、批量对比、候选结果，不直接进入正式成果 |

| DXF 生成 | 不做/未来 | 成果输出中可禁用显示 | 当前不做真实 DXF |
| 插件市场 | 不做 | 不展示 | 可内置方法和未来自定义方法，但不做 VSCode marketplace |

## 5. 设计稿交付页序

设计师应按以下顺序出图。每一页都应符合 VSCode-like 工作台骨架，不允许变成互不相关的网页。

| 页序 | 设计稿名称 | 目的 | 是否主流程 |
| --- | --- | --- | --- |
| 01 | 工作台壳层与工程树 | 定义全局结构、菜单、Explorer、状态栏、Tabs、面板 | 是 |
| 01A | 新建工程弹窗 | 通过 File 或 Explorer 更多菜单创建工程 | 是，入口弹窗 |
| 01B | 打开工程弹窗 | 选择最近工程或本地工程文件夹 | 是，入口弹窗 |
| 01C | 工程设置窗口 | 管理工程基本信息、场址基准、数据目录、本地数据库 | 是，配置窗口 |
| 02 | 项目/点位数据 | 当前工程和点位总览，进入导入/检查/分层 | 是 |
| 03 | 数据导入 | 文件选择、字段映射、预览、导入预检和提交 | 是 |
| 04 | 数据检查 | 质量问题列表、定位、修复建议、是否允许进入分层 | 是 |
| 05 | 地层分层默认页 | 当前点位分层结果、层位、曲线、证据、采纳操作 | 是 |
| 05B | 地层分层方法选择器 | 按输出、土类、输入可用性选择分层方法 | 是，05 内弹窗/抽屉 |
| 05A | 地层分层对比/详情态 | 多方案对比、边界差异、证据详情、日志折叠 | 是，高级状态 |
| 06 | 参数解译默认页 | 选择分层方案，配置参数方法，展示参数曲线和统计 | 是 |
| 06A | 参数方法选择器 | 按参数、土类、输入可用性筛选方法 | 是，弹窗/抽屉 |
| 07 | 成果输出 | adopted 结果预检、报告预览、导出记录 | 是 |
| 08 | 方法实验室 | 方法接入、测试、能力声明、结果预览、日志 | 否，高级 |
| 09 | 研究模式 | 批量试算、多方法候选、科研对比，不写正式成果 | 否，高级 |
| 10 | 全局状态集 | 空状态、错误、阻塞、只读、缺少数据、未采纳状态 | 是，验收必需 |

页序说明：

- `01-10` 是完整设计包的编号，不等于开发优先级。
- 第一轮优先画 `01/01A/01B/01C/02/05/06/07/10`，用于先锁定工作台骨架、工程首页、地层分层、参数解译和成果闭环。
- 第二轮补 `03/04/05A/05B/06A/08/09`，用于补齐导入检查、方法选择、科研对比和高级能力。
- `05A/05B/06A` 是页面 05/06 的局部状态或弹窗，不是新的主流程入口。

## 6. 全局信息架构

### 6.1 顶部菜单栏

菜单语言应为中文，必要技术词可保留英文。

建议菜单：

| 菜单 | 常用项 | 说明 |
| --- | --- | --- |
| 文件 | 新建工程、打开工程文件夹、最近工程、工程设置、退出 | 工程级操作 |
| 编辑 | 撤销、重做、复制、粘贴 | 仅在可编辑控件中生效 |
| 视图 | Explorer、属性面板、底部面板、重置布局 | 工作台布局控制 |
| 转到 | 上一步、下一步、打开当前点位、打开当前方案 | 导航，不做命令面板 |
| 运行 | 运行数据检查、运行地层分层、运行参数解译 | 业务运行入口 |
| 输出 | 打开成果输出、导出当前结果、查看导出记录 | 成果相关 |
| 帮助 | 关于、数据说明、方法说明 | 简短帮助，不放长篇文档 |

顶部菜单不是功能堆放区。高频动作还要出现在对应页面的局部工具栏里。

### 6.2 Activity Bar

左侧深色条只放全局入口：

| 图标入口 | 作用 | 默认行为 |
| --- | --- | --- |
| Explorer | 工程树和主工作流 | 默认选中 |
| 问题 | 打开底部问题面板 | 不切换主页面 |
| 输出 | 打开底部运行日志/导出记录 | 不切换主页面 |
| 成果 | 打开成果输出或输出文件列表 | 有可用成果包时高亮 |
| 设置 | 打开工程设置 | 工程已打开时可用 |

禁止把所有业务页面都堆成 Activity Bar 图标。业务页面应通过 Explorer 工作流节点进入。

### 6.3 Explorer 工程树

Explorer 是项目导航，不是说明文档。

推荐树结构：

```text
工程资源
  SIGS-OGLab 工程
    营口样例 / CPT9-19-S1
      项目/点位数据
      数据导入
      数据检查
      地层分层
      参数解译
      成果输出
  最近工程
    珠海试验工程
    宁波复核工程
```

节点规则：

- 点击工作流节点必须打开或激活对应 Editor Tab。
- 当前节点要有明确选中态。
- 节点右侧可显示短状态，如 `就绪`、`需检查`、`阻塞`，不能和文字重叠。
- 工程树底部可以显示一句状态提示，但不能占用主要空间。
- 不要默认展示没有业务意义的系统文件夹、内部目录、方法运行路径。

### 6.4 Editor Tabs

Tabs 展示当前打开的业务文档。

常见 Tab：

- `项目/点位数据`
- `数据导入`
- `数据检查`
- `地层分层`
- `参数解译`
- `成果输出`
- `方法实验室`

Tab 规则：

- 当前 Tab 背景接近白色，未选中 Tab 接近 `#F3F3F3`。
- 每个 Tab 可关闭，但关闭不等于删除业务数据。
- 从 Explorer 点击同一节点时复用已打开 Tab。
- 脏状态可用小圆点或 `*` 表示，但要有真实未保存状态支撑。

### 6.5 右侧属性面板

右侧面板显示当前选中对象的短属性。

对象可以是：

- 当前工程。
- 当前点位。
- 当前导入批次。
- 当前数据问题。
- 当前分层方案。
- 当前层或边界。
- 当前参数方案。
- 当前参数方法。
- 当前输出包。

规则：

- 默认只放 5 到 8 条关键属性。
- 长日志、完整 JSON、内部路径不放右侧面板。
- 没有选中对象时显示简短空状态：`选择一个点位、层位或参数结果查看详情。`

### 6.6 底部面板

底部面板是辅助信息区，默认可折叠。

常见 Tab：

- `问题`
- `运行日志`
- `导出`
- `方法对比`
- `预检`

规则：

- 阻塞问题必须能在底部面板看到。
- 日志只显示用户能理解的摘要，开发日志要进入高级详情。
- 默认不要占据过多高度，除非用户主动展开。

### 6.7 状态栏

最底部蓝色状态栏显示真实状态：

```text
就绪 | 当前工程：营口样例 | 当前点位：CPT09 | 数据：CPTU 16,653 点 | SQLite 本地模式
```

规则：

- 只放全局短状态。
- 不放长句说明。
- 错误状态可以短暂显示，但详细内容进入底部问题面板。

## 7. 核心数据对象

设计师不需要实现数据结构，但需要理解这些对象对应哪些界面。

| 对象 | 中文名 | 主要出现位置 | 用户理解 |
| --- | --- | --- | --- |
| Project | 工程 | Explorer、项目/点位数据、工程设置 | 当前工作文件夹和本地数据容器 |
| Point | 点位 | 项目/点位数据、所有主流程页 | 一个 CPT/CPTU 测点 |
| ImportBatch | 导入批次 | 数据导入、数据检查 | 一次导入的文件和解析结果 |
| DataQualityIssue | 数据质量问题 | 数据检查、底部问题面板 | 阻塞、警告、提示 |
| Method | 方法 | 方法实验室、方法选择器 | 一种分层或参数计算方法 |
| MethodCapability | 方法能力 | 方法实验室、方法选择器 | 该方法能产出什么 |
| LayerScheme | 分层方案 | 地层分层、参数解译、成果输出 | 一套层位、边界、土类和来源 |
| ClassificationEvidence | 分类证据 | 地层分层 | SBT/SBTn/Ic 等证据视图 |
| ParameterScheme | 参数解译方案 | 参数解译、成果输出 | 一套参数方法选择和计算结果 |
| ParameterSlot | 参数项 | 参数解译 | φ'、Su、γ、OCR、Dr 等 |
| ParameterSeries | 参数曲线 | 参数解译 | 随深度变化的参数结果 |
| MethodRun | 方法运行记录 | 方法实验室、底部日志 | 一次运行，不等于正式成果 |
| AdoptedOutputPackage | 已采纳成果包 | 成果输出 | 被采纳并允许输出的结果集合 |

方法输出路由规则：

```text
method outputs LayerScheme            -> 地层分层页
method outputs ClassificationEvidence -> 地层分层页的证据视图
method outputs ParameterSeries        -> 参数解译页
method outputs ParameterScheme        -> 参数解译页
method metadata/logs/debug output     -> 方法实验室
adopted schemes                       -> 成果输出
```

不得为每个方法单独做一个主页面。pyCPT、Groundhog、Ic/SBT、自定义公式都只是填入通用能力槽。

### 7.1 MethodCapability 字段合同

方法能力声明用于筛选方法和路由结果。它是内部合同，默认 UI 只显示中文摘要。

| 字段 | 示例 | UI 用途 |
| --- | --- | --- |
| capabilityId | `layer.ic_sbt.v1` | 内部识别 |
| outputType | `LayerScheme` / `ClassificationEvidence` / `ParameterSeries` | 决定结果去向 |
| outputLabel | `分层方案` / `分类证据` / `参数曲线` | 用户可见结果类型 |
| targetParameter | `φ'` / `Su` / `γ` / 空 | 参数方法筛选 |
| applicableSoil | `砂土` / `黏土` / `过渡层` / `全部` | 方法选择器过滤 |
| requiredInputs | `qc, fs, u2, depth` | 缺输入时给出原因 |
| engineeringUseLevel | `正式` / `参考` / `实验` | 默认排序和风险提示 |
| runStatus | `可用` / `缺输入` / `未安装` / `运行失败` | 按钮启用条件 |
| failureReason | `缺少 u2` | 不可用说明 |
| resultScope | `当前点位` / `批量点位` | 是否能在当前页运行 |
| sourceLabel | `Robertson 1990` | 简短来源 |
| detailVisibility | `默认` / `高级` / `开发` | 是否在默认 UI 显示 |

能力声明只回答“这个方法能产出什么、当前能不能跑、跑完去哪里”。许可证、运行路径、stdout、完整 artifact 列表等放在方法实验室高级详情，不进入主流程默认页。

### 15.10 采纳与参数输入规则

为避免“采纳方案”和“设为参数输入”两个动作混乱，第一版按下列规则：

| 动作 | 作用 | 是否进入正式参数解译 | 是否允许成果输出 |
| --- | --- | --- | --- |
| 保存草稿 | 把候选结果保存为可编辑草稿 | 否，仅可试算 | 否 |
| 采纳为当前分层 | 把草稿或候选确认成当前点位正式分层 | 是，自动成为参数解译默认输入 | 是，仍需参数方案也采纳 |
| 用于参数试算 | 不改变正式分层，只把当前方案带到参数页试算 | 否，只能试算 | 否 |
| 取消采纳/替换采纳 | 需要二次确认并记录历史 | 替换后新采纳方案成为默认输入 | 依赖新预检 |

正式链路只有一个默认分层输入：当前已采纳分层方案。其他方案只能试算、对比或转草稿。

### 15.11 地层分层方法选择器

地层分层方法选择器是页面 05 内的抽屉或弹窗，不是新的主流程页。

触发规则：

- 当前点位有多个可用分层方法时，点击 `运行分层` 打开选择器。
- 当前点位只有一个默认可用方法时，可以直接运行，但运行前仍显示方法名和结果状态。
- 当前点位没有可用方法时，显示不可用原因，并引导到数据检查或方法实验室。

布局：

```text
Header: 选择地层分层方法
Filter row: 输出类型 | 数据可用性 | 用途等级 | 来源
Method list: 可用方法优先，缺输入方法灰显
Right/detail: 方法摘要、所需输入、结果去向、限制
Footer: 运行为候选方案 | 取消
```

运行结果默认状态为 `候选`。用户需要保存为草稿或采纳后，才会进入正式工程链路。

## 16. 页面 05A：地层分层对比/详情态

### 16.1 页面目的

服务科研对比和工程复核，不替代默认分层页。

### 16.2 内容

- 多方案边界对齐图。
- 各方案层位差异摘要。
- 土类一致率或冲突区间。
- 方法来源和输入要求。
- 候选方案是否可采纳。

### 16.3 布局建议

对比应进入底部面板展开态或中央次级 Tab，而不是改变主流程页面结构。

```text
Center upper: 当前方案主剖面
Center lower or Bottom expanded: 多方案对比
Right: 选中差异区间详情
```

### 16.4 交互

- 选择两个或多个方案进行对比。
- 点击差异区间，曲线和表格同步定位。
- 允许从候选方案生成草稿，但不能直接输出。

### 16.5 对比能力边界

为避免页面 05A、底部面板和研究模式职责重叠，按下表拆分：

| 位置 | 面向对象 | 数据粒度 | 入口 | 可产生正式结果 |
| --- | --- | --- | --- | --- |
| 地层分层默认页底部 `方法对比` | 工程用户复核当前点位 | 当前点位、少量方案 | 05 页底部面板 | 不能，只辅助采纳判断 |
| 页面 05A 对比/详情态 | 工程复核 + 科研对比 | 当前点位、多方案、多边界 | 从 05 底部展开或 Tab 打开 | 不能直接输出，可生成草稿 |
| 研究模式 | 科研人员和方法维护者 | 多点位、批量试算、方法矩阵 | 高级入口 | 不能，需发送到主流程成为候选/草稿 |

原则：默认页先看当前正式工作；对比页看当前点位差异；研究模式看批量和方法探索。任何研究或对比结果都不能绕过采纳进入成果输出。

## 17. 页面 06：参数解译默认页

### 17.1 页面目的

这是第二个核心页面。它要基于一个明确的分层方案，运行参数方法并展示可采纳的参数解译结果。

页面默认回答：

- 当前参数解译使用哪套分层方案？
- 每个参数使用什么方法？
- 砂土、黏土、过渡层、未知层分别如何处理？
- 参数曲线是什么样？
- 哪些深度区间无效或需要复核？
- 当前方案能否输出？

### 17.2 当前实现映射

- Route：`parameters`
- 页面：`InterpretationPage`
- 工作流名称：`参数解译`

### 17.3 进入前提

参数解译必须消费一个分层方案。没有可用分层方案时，不进入正式参数解译。

| 分层方案状态 | 正式参数解译 | 说明 |
| --- | --- | --- |
| 已采纳 | 允许 | 默认正式输入 |
| 草稿 | 可试算 | 输出前必须采纳 |
| 候选 | 仅试算 | 不能直接正式输出 |
| 研究结果 | 仅研究模式 | 不写正式成果 |
| 投影/调试结果 | 不允许 | 只能作为证据或参考 |
| 无效 | 不允许 | 返回地层分层或数据检查 |

### 17.4 推荐布局

```text
Top command row:
  当前点位 | 分层方案选择器 | 参数方案选择器 | 运行参数解译 | 保存草稿 | 采纳参数方案

Local left:
  参数方案列表 / 参数项导航

Center:
  曲线剖面 + 分层背景
  参数项配置区
  层内统计表

Global right:
  当前参数项/方法/层统计详情

Bottom:
  方法可用性 | 运行日志 | 参数方案对比 | 输出预检
```

### 17.5 参数项

第一版建议支持这些通用参数项的 UI，不要求所有算法都已完整实现。内部对象可叫 `ParameterSlot`，用户界面统一叫“参数项”。

| 参数项 | 中文名 | 常见适用对象 | 设计要求 |
| --- | --- | --- | --- |
| `φ'` | 有效内摩擦角 | 砂土、粉砂、部分过渡层 | 方法选择器需过滤砂类适用方法 |
| `Su` | 不排水抗剪强度 | 黏土、软黏土 | 方法选择器需过滤黏土适用方法 |
| `γ` | 重度 | 全层或按土类 | 可显示默认值、计算值、人工值 |
| `OCR` | 超固结比 | 黏土为主 | 输入不足时显示不可用原因 |
| `Dr` | 相对密实度 | 砂土为主 | 输入不足时显示不可用原因 |

混合层、过渡层、未知层不要自动套用砂土或黏土方法。默认需要用户确认或显示阻塞。

### 17.6 方法选择器

方法选择器不显示所有方法，只显示当前参数项可用的方法。

过滤条件：

- 输出参数：例如 `φ'`、`Su`。
- 适用土类或土行为类型。
- 需要的输入字段是否存在。
- 当前方法是否已安装/可运行。
- 工程用途等级：正式、参考、实验。

每个方法行显示：

- 方法名称。
- 输出参数。
- 适用土类。
- 所需输入。
- 状态：可用、缺输入、实验、不可用。
- 简短来源。

### 17.7 中央结果视图

中央视图应以结果为主：

- 参数曲线随深度变化。
- 背景显示已选分层方案。
- 无效区间用明确标记。
- 层内统计表显示均值、范围、采用值、异常标记。

曲线过多时，不要一次全部展开。可按参数项切换或多选对比。

### 17.8 交互

| 操作 | 结果 |
| --- | --- |
| 选择分层方案 | 刷新参数项可用性和分层背景 |
| 点击参数项 | 中央显示对应参数曲线和方法配置 |
| 点击方法选择 | 打开方法选择器 |
| 运行参数解译 | 生成参数解译方案或更新草稿 |
| 点击曲线点/层 | 右侧显示该深度或层内统计详情 |
| 采纳参数方案 | 成为成果输出可用输入 |

### 17.9 空状态和阻塞状态

没有分层方案：

- 显示 `参数解译需要先选择地层分层方案`。
- 主按钮：`进入地层分层`。

分层方案未采纳：

- 显示 `当前方案可试算，正式输出前需要采纳`。
- 可以运行试算，但不能输出。

缺输入字段：

- 方法选择器中显示缺少字段。
- 底部预检给出阻塞详情。

### 17.10 禁止内容

- 不让用户先选一堆方法再发现没有分层输入。
- 不把所有方法无差别塞进一个下拉框。
- 不在默认页展示内部 runner 输出。

## 22. 全局交互逻辑

### 22.1 主流程状态推进

```text
数据导入成功
  -> 数据检查可运行
数据检查无阻塞
  -> 地层分层可运行
地层分层有已采纳方案
  -> 参数解译可正式运行
参数解译有已采纳方案
  -> 成果输出可生成
```

每一步如果缺少前置条件，页面应给出明确跳转，而不是显示空白或长说明。

### 22.2 对象联动

| 用户选择 | 应联动刷新 |
| --- | --- |
| 当前工程 | Explorer、状态栏、所有页面数据 |
| 当前点位 | 右侧面板、主流程页面、状态栏 |
| 当前分层方案 | 地层分层中央视图、参数解译前置输入 |
| 当前层/边界 | 右侧详情、表格选中、曲线高亮 |
| 当前参数方案 | 参数曲线、层内统计、输出预检 |
| 当前问题 | 数据定位、右侧详情、底部问题面板 |

### 22.3 编辑与保存

- 工程设置、分层草稿、参数草稿需要明确未保存状态。
- 采纳动作必须二次确认。
- 删除或覆盖正式结果必须二次确认。
- 方法运行生成候选，不自动覆盖已采纳结果。

### 22.4 全局选择状态和 source of truth

后续实现不能让每个页面各自维护一套当前对象。工作台需要一个全局上下文，负责同步 Explorer、Tabs、右侧面板、底部面板和状态栏。

| 全局状态 | 来源 | 更新方式 | 影响范围 |
| --- | --- | --- | --- |
| 当前工程 | 打开/新建工程 | File 菜单、打开工程弹窗 | 全部页面、状态栏、Explorer |
| 当前点位 | 点位列表或工程树 | 点击点位、打开页面时带入 | 数据检查、分层、参数、输出 |
| 当前分层方案 | 地层分层页 | 选择、保存草稿、采纳 | 参数解译、成果输出、右侧面板 |
| 当前参数解译方案 | 参数解译页 | 选择、保存草稿、采纳 | 成果输出、右侧面板 |
| 当前选中对象 | 任意页面 | 点击层、边界、问题、方法、输出项 | 右侧属性面板 |
| 当前底部面板 | Activity Bar 或页面动作 | 打开问题、日志、预检、对比 | 底部面板 |

路由可以不在第一版暴露复杂 URL，但内部导航必须携带当前对象 ID。Explorer 点击、顶部菜单和页面按钮进入同一页时，必须复用同一全局上下文。

### 22.5 页面-对象-动作矩阵

| 页面 | Route / Page | 读取对象 | 写入对象 | 主要命令 | 启用条件 | 状态变体 |
| --- | --- | --- | --- | --- | --- | --- |
| 项目/点位数据 | `project-overview` / `ProjectOverviewPage` | Project、Point、DataQualityIssue、AdoptedOutputPackage | 当前点位选择 | 选择点位、进入下一步、打开工程设置 | 工程已打开 | 无点位、待检查、阻塞、可继续 |
| 数据导入 | `data-import` / `DataImportPage` | Project、ImportBatch 草稿 | ImportBatch、Point 数据 | 选择文件、映射字段、预检、提交 | 工程可写 | 无文件、预检失败、可提交、导入成功 |
| 数据检查 | `data-check` / `DataCheckPage` | Point 数据、ImportBatch | DataQualityIssue、检查记录 | 运行检查、过滤问题、定位问题 | 有点位数据 | 未检查、阻塞、警告、通过 |
| 地层分层 | `stratification` / `StratificationPage` | Point、DataQualityIssue、LayerScheme、ClassificationEvidence | LayerScheme 草稿/采纳状态 | 运行分层、保存草稿、采纳、用于参数试算 | 数据检查无阻塞 | 无方案、候选、草稿、已采纳、无效 |
| 参数解译 | `parameters` / `InterpretationPage` | Point、LayerScheme、MethodCapability、ParameterScheme | ParameterScheme 草稿/采纳状态 | 选择参数项、选方法、运行、采纳 | 有可用分层方案 | 无分层、试算、草稿、已采纳、缺输入 |
| 成果输出 | `export` / `ExportPage` | Adopted LayerScheme、Adopted ParameterScheme、DataQualityIssue | AdoptedOutputPackage、导出记录 | 预检、生成成果包、打开输出文件 | 分层和参数均已采纳 | 不可生成、预检警告、可生成、已生成 |
| 方法实验室 | `method-lab` / `MethodLabPage` | Method、MethodCapability、MethodRun | MethodRun、测试输出 | 刷新方法、运行测试、打开结果去向 | 高级入口打开 | 未安装、缺输入、可运行、运行失败 |
| 研究模式 | `research` / `ResearchModePage` | Point、MethodCapability、MethodRun | 候选结果、研究记录 | 批量试算、对比、发送到主流程 | 高级入口打开 | 无任务、运行中、候选、失败 |

### 22.6 状态机

#### 分层方案状态

```text
方法运行 -> 候选
候选 -> 保存草稿 -> 草稿
候选 -> 采纳为当前分层 -> 已采纳
草稿 -> 采纳为当前分层 -> 已采纳
已采纳 -> 替换采纳 -> 只读历史 + 新已采纳
任意状态 -> 输入失效/方法失败 -> 无效
```

规则：

- `已采纳` 自动成为正式参数解译输入。
- `候选` 和 `草稿` 只能试算，不能直接输出。
- `只读历史` 只能查看和对比，不能编辑。

#### 参数解译方案状态

```text
参数试算 -> 试算
试算 -> 保存草稿 -> 草稿
草稿 -> 采纳参数方案 -> 已采纳
已采纳 -> 替换采纳 -> 只读历史 + 新已采纳
缺输入/分层失效 -> 无效
```

规则：

- 参数方案必须绑定一个分层方案版本。
- 如果绑定的分层方案被替换，参数方案进入 `需复核` 或 `无效`，不能直接输出。

#### 方法运行记录状态

```text
待运行 -> 运行中 -> 已完成 -> 已路由
待运行 -> 运行失败
运行中 -> 已取消
```

规则：

- 方法运行记录不是正式成果。
- 运行结果必须路由为候选分层、候选参数或证据视图。

#### 成果包状态

```text
预检失败 -> 不可生成
预检警告 -> 可生成但需提示
预检通过 -> 可生成
生成成功 -> 已生成
源结果变更 -> 需重新生成
```

规则：

- 成果包只消费已采纳分层方案和已采纳参数解译方案。
- 研究、候选、调试结果不能直接进入成果包。

## 23. 可视化规则

### 23.1 CPT/CPTU 曲线

曲线视图要满足工程读图习惯：

- 深度轴向下增大。
- 曲线分轨显示，避免重叠不可读。
- 网格线清楚但不喧宾夺主。
- 当前层位背景和边界要能读出深度。
- 悬停显示深度和值。

### 23.2 Layer track

分层轨道应显示：

- 层号。
- 土类短名。
- 深度范围。
- 当前选中层高亮。
- 不确定边界或人工边界样式区别。

颜色不要靠随机彩虹。土层颜色应服务区分，不要破坏 VSCode-like 主界面。

### 23.3 SBT/分类证据

SBT 图和分类证据是地层分层的证据，不是独立主流程。

默认可以用一个证据面板或次级 Tab 展示：

- SBT 图。
- Ic/SBTn 分类轨道。
- 分类点云。
- 分类说明。

### 23.4 参数曲线

参数曲线应与分层背景联动：

- 同一深度范围内能看到参数值和层位。
- 无效区间要标记。
- 每个参数项可单独显示，也可多选叠加。
- 层内统计和曲线选中互相联动。

## 24. 全局空状态、错误状态和只读状态

| 状态 | 应显示 | 不应显示 |
| --- | --- | --- |
| 未打开工程 | 打开工程、新建工程、最近工程 | 空白工作台 |
| 工程无点位 | 导入数据入口、打开样例入口 | 方法页面 |
| 数据未检查 | 运行数据检查入口 | 假装可正式解译 |
| 数据有阻塞 | 阻塞摘要、跳转到数据检查 | 长日志替代结论 |
| 无分层方案 | 运行分层入口 | 空图表 |
| 分层未采纳 | 试算可用、正式输出不可用 | 直接进入成果 |
| 参数未采纳 | 试算可用、输出阻塞 | 直接生成报告 |
| 只读工程 | 状态栏和页面顶部提示 | 隐藏保存失败 |

### 24.1 页面 10：全局状态集画板要求

`页面 10` 是设计验收画板，不是用户主流程页。它用于一次性检查所有页面共用状态是否有统一画法。

必须覆盖：

| 状态画板 | 落点 | 必须包含 |
| --- | --- | --- |
| 未打开工程 | 中央 Editor 空状态 | 新建工程、打开工程、最近工程 |
| 工程无点位 | 项目/点位数据页中央 | 导入数据、打开样例 |
| 数据阻塞 | 页面顶部提示 + 底部问题面板 | 阻塞数量、主原因、跳转到数据检查 |
| 地层无方案 | 地层分层页中央 | 运行分层方法、返回数据检查 |
| 分层未采纳 | 地层页顶部状态 + 参数页空状态 | 采纳为当前分层、用于参数试算 |
| 参数无方案 | 参数解译页中央 | 选择参数项、运行参数解译 |
| 输出不可生成 | 成果输出页顶部 + 预检列表 | 缺少分层/参数/数据阻塞原因 |
| 只读工程 | 顶部提示 + 禁用按钮态 | 哪些动作不可用、为什么不可用 |
| 运行中 | 页面工具栏 + 底部日志摘要 | 进度、取消、不会遮挡结果 |
| 运行失败 | 页面顶部提示 + 右侧详情 | 失败原因、重试、查看日志 |

状态画法规则：

- 页面顶部只放一句结论和一个主动作。
- 底部面板放问题列表或运行摘要。
- 右侧面板放选中问题/对象详情。
- 中央空状态只在没有核心结果时出现；有结果时不能用大空状态遮挡结果。
- 所有状态必须使用固定状态词表，不能每页自造同义词。

## 25. 文案规则

### 25.1 中文优先

所有面向用户的 UI 文案使用中文。下列技术词可保留：

- `CPT`
- `CPTU`
- `SBT`
- `SBTn`
- `Ic`
- `qc`
- `fs`
- `u2`
- `SQLite`

- `ParameterScheme`

这些英文技术词只允许在方法实验室、高级详情、开发文档或表结构说明中出现。主流程页面应使用下面的用户可见词。

### 25.2 用户可见词表

| 内部/技术词 | 主流程 UI 用词 | 出现位置 |
| --- | --- | --- |
| `LayerScheme` | 分层方案 | 地层分层、参数解译、成果输出 |
| `ParameterScheme` | 参数解译方案 | 参数解译、成果输出 |
| `ParameterSlot` | 参数项 | 参数解译 |
| `MethodRun` | 方法运行记录 | 方法实验室、底部日志 |
| `AdoptedOutputPackage` | 已采纳成果包 | 成果输出 |
| manifest | 导出清单 | 成果输出高级详情 |
| artifacts | 输出文件 | 方法实验室高级详情 |
| provenance | 来源追溯 | 方法实验室或成果详情 |
| warnings | 警告 | 问题面板或方法实验室 |
| runner | 运行器 | 仅开发/高级调试，不进默认 UI |
| registry | 方法注册表 | 仅开发/高级调试，不进默认 UI |
| draft package | 草稿结果包 | 仅开发/高级调试，不进默认 UI |

状态词固定：

| 类型 | 固定词 |
| --- | --- |
| 通用状态 | 就绪、需检查、阻塞、只读、运行中、已完成 |
| 分层状态 | 无方案、候选、草稿、已采纳、只读历史、无效 |
| 参数状态 | 无方案、试算、草稿、已采纳、无效 |
| 输出状态 | 不可生成、预检警告、可生成、已生成 |
| 方法状态 | 可用、缺输入、实验、未安装、运行失败 |

### 25.3 文案要短

默认页不写大段解释。需要说明时使用：

- 1 行状态。
- 1 行原因。
- 1 个下一步动作。

示例：

```text
当前没有已采纳分层方案。
参数解译需要先选择或采纳一套分层方案。
[进入地层分层]
```

### 25.4 避免内部开发词

默认界面不出现：

- runner
- registry
- draft package
- projection safety
- stdout
- stderr
- fixture
- local QA
- internal route

这些只能在方法实验室或开发日志中出现。

## 27. 给挑刺设计师的审阅问题

审阅者假设自己完全不了解历史，只读本文档，需要回答：

1. 是否能明确软件是干什么的？
2. 是否能明确第一页、第二页、第三页分别要画什么？
3. 是否能明确每个页面的区域、组件和交互？
4. 是否能判断哪些功能是已有、拟做、未来、不做？
5. 是否存在页面职责重叠？
6. 是否存在默认界面过度解释、过度方法化、过度开发化？
7. 是否能看出地层分层和参数解译是产品重点？
8. 是否能画出 VSCode-like，而不是普通后台系统？
9. 是否缺少关键弹窗、状态或错误页？
10. 是否有任何新增功能没有承接窗口或页面？

审阅结论必须分为：

- `blocking`：阻止设计继续，必须补文档。
- `risk`：可以继续，但需要设计阶段特别注意。
- `nit`：小问题，不阻止继续。

## 30. 当前实现与设计差距

| 差距 | 影响 | 设计要求 |
| --- | --- | --- |
| 部分页面仍像 demo 或调试页 | 用户不知道核心结果在哪里 | 地层/参数页默认展示结果，不展示内部日志 |

| 方法实验室容易抢主流程 | 地层/参数目标被稀释 | 方法实验室只做高级调试，结果路由回主页面 |

| 旧英文和内部词残留 | 不像中文工程软件 | 默认 UI 全部中文化，内部词隐藏 |

| 验收项 | 通过标准 |
