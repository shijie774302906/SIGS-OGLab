## 2. 页面目标

让用户把外部 CPT/CPTU 文件导入当前工程，确认字段映射和数据预览，通过预检后提交为导入批次。

页面默认回答：

- 当前导入批次里有哪些文件？
- 哪些文件解析通过、未解析或被忽略？
- 当前文件字段如何映射到标准字段？
- 数据预览是否可信？
- 预检是否允许提交？
- 提交后进入哪个主流程步骤？

## 3. 布局定义

采用 VSCode-like 工作台结构：

- 左侧 Explorer：工程树中选中 `数据导入`。
- 顶部 Editor Tabs：`数据导入` 为当前激活 Tab。
- 中央 Editor：上方导入动作和解析设置，中部文件列表与字段映射，下方数据预览。
- 右侧属性面板：当前导入批次属性和预检摘要。
- 底部面板：导入问题列表，默认显示问题而不是长日志。
- 状态栏：当前工程、当前点位、数据点数和本地模式。

## 7. 后续实现注意

- 当前代码已有 `DataImportPage`、预览、映射、提交和导入服务，后续实现重点是重排，而不是重造导入逻辑。
- `智能映射` 可先对应现有候选映射确认能力，避免扩成不可控的 AI 自动导入。
- `查看详细报告` 建议优先实现为右侧属性详情或底部面板展开态，不新增主流程页面。
- 预检失败时必须禁用 `提交导入`，并在底部问题表中给出可定位的问题。
- 底部默认页签不得保留 `终端`；`输出/日志` 也不得作为默认导入页签暴露。主流程默认建议为 `问题 / 预检 / 提交记录`，长日志只能由用户主动展开进入日志详情。

## 11. 目标窗口和面板

### 11.1 导入设置弹窗

入口：顶部 `设置`。

内容：

- 文件格式：CSV / Excel。
- 编码：UTF-8 等。
- 分隔符：逗号、Tab、分号等。
- 单位策略：显示换算并重新预检。
- 深度列：必须映射。

动作：

- `取消`：关闭弹窗，不改变草稿。
- `应用并预检`：刷新字段映射、数据预览和右侧预检结果。

### 11.2 智能映射候选

入口：字段映射区 `智能映射`。

规则：

- 只生成候选映射，不自动提交。
- 显示标准字段、候选源字段、置信度、操作。
- 低置信度或无匹配时必须要求用户复核或跳过。
- 确认后刷新数据预览和预检。

### 11.3 预检详细报告

入口：右侧 `查看详细报告` 或底部问题行。

内容：

- 问题等级：提示、警告、阻塞。
- 问题代码。
- 来源：单位检查、字段映射、重复深度、范围检查等。
- 文件、行、列。
- 用户动作：定位问题、返回映射、重新预检。

规则：

- 不新增主流程页面。
- 默认不展示长日志。
- 仅用户主动展开时显示详细日志或解析记录。

## 12. 状态覆盖

| 状态 | 默认表现 | 主动作 | 禁止内容 |
| --- | --- | --- | --- |
| 无文件 | 中央显示 `请选择 CPT/CPTU 数据文件` | `选择文件` | 空表格占位、长说明 |
| 选择中/解析中 | 文件列表显示进度，提交禁用 | 等待或取消解析 | 提交导入 |
| 解析成功 | 文件状态为 `解析通过`，预览刷新 | `解析预检` 或 `提交导入` | 不经预检直接写库 |
| 预检警告 | 右侧显示 `预检结果：警告，可提交`，底部列出可定位问题 | 继续提交或查看详情 | 只用日志解释警告 |
| 预检阻塞 | 右侧显示阻塞摘要，提交禁用 | `查看详细报告` / `定位问题` | 允许提交 |
| 提交成功 | 右侧显示写入成功和下一步 `数据检查` | `进入数据检查` | 留在导入页不提示下一步 |
| 写入失败 | 保留草稿并显示失败原因 | 重试、导出问题或查看详情 | 清空草稿或吞掉错误 |
| 只读工程 | 导入动作禁用，仅允许预览 | 打开可写工程或另存 | 假装可写入 |
| 清空草稿 | 二次确认 | `确认清空` | 删除正式数据库记录 |

## 13. 实现阻断条件

实现或后续审图时，以下情况应标为 `blocking`：

- 默认屏幕看不到文件状态、字段映射、预检结果或下一步动作。
- 预检阻塞时 `提交导入` 仍可点击。
- `智能映射` 自动写库或自动提交。
- 默认底部页签暴露 `终端`、内部长日志、内部路径、runner、registry、draft package。
- `设置`、`查看详细报告` 等新增入口没有目标弹窗、面板、接口状态或隐藏决定。
- 错误状态只写“失败”，没有告诉用户文件、行、列或下一步处理方式。
