# 界面设计方案

## 设计定位

产品名称：`SIGS-OGLab | 海上风电岩土勘察解译`

第一版定位为海上风电岩土勘察数据工作台，服务对象是岩土工程师、勘察数据处理人员和项目审查人员。界面不复刻原操作手册中的传统菜单工具条风格，而是采用现代 WinUI 桌面工作台：流程清晰、数据密集、参数可追溯、结果可审计。

界面的单一目标：

> 让用户把 CPTU 样例数据导入进来，检查数据质量，完成 CPTU 解译，整理岩土参数，并导出第一版勘察解译成果。

## 视觉方向

关键词：

- 专业
- 克制
- 数据优先
- 海洋工程
- 可审计

不采用：

- 老式 Office 工具条堆叠
- 原操作手册中的旧桌面软件外观
- 过重的品牌装饰
- 大面积渐变背景
- 卡片套卡片
- 永久占位的右侧参数栏

## 设计记忆点

第一版的视觉记忆点是“深度剖面工作区”。

在测试解译页中，中央区域以深度为纵轴，同时展示：

- 分层柱状图
- CPTU `qt` 曲线
- 侧摩曲线
- 孔压 `U2` 曲线
- 摩阻比 `Fr` 曲线
- 解译结果表

这个元素来自 CPTU 数据本身，而不是装饰。它应该成为软件最有辨识度的界面。

## 色彩系统

采用浅色为主、支持深色模式的 WinUI 主题资源。颜色尽量通过资源字典管理，不在页面中散落硬编码。

建议色彩令牌：

```text
PrimaryBlue      #0F63D8  主操作、当前流程、选中状态
MarineInk        #14213D  标题、主文本、深色图标
SeaGrid          #D7E2F0  分隔线、网格线、坐标网
SignalGreen      #168A4A  通过、完成、有效数据
WarningAmber     #D97706  警告、待处理
ErrorRed         #D92D20  错误、阻塞问题
CPTUQtRed        #E53935  qt 曲线
CPTUFsBlue       #2563EB  侧摩曲线
CPTUU2Green      #16A34A  孔压曲线
CPTUFrViolet     #7C3AED  Fr 曲线
```

使用原则：

- `PrimaryBlue` 只用于主要操作和当前流程，不到处染色。
- 曲线颜色固定，保证所有页面、图例和导出预览一致。
- 状态颜色只表达状态，不作为装饰。
- 背景、边框、卡片优先使用 WinUI theme resources。

## 字体与层级

优先使用 Windows 平台字体：

- 中文与正文：`Microsoft YaHei UI` 或系统默认 UI 字体
- 英文和数字：`Segoe UI Variable`
- 数据表和曲线坐标：等宽数字显示，保持小数对齐

层级建议：

```text
应用标题        20-22px Semibold
页面标题        18-20px Semibold
模块标题        15-16px Semibold
正文/表格       13-14px Regular
辅助说明        12px Regular
状态/标签       12px Medium
```

界面文字规则：

- 按钮使用动作动词，如“导入数据”“运行解译”“保存方案”。
- 错误信息直接说明问题和修复方式。
- 同一动作在按钮、日志、提示中使用同一个名称。

## 总体布局

```text
┌──────────────────────────────────────────────┐
│ 顶部栏：SIGS-OGLab | 海上风电岩土勘察解译       │
│         当前项目 / 搜索 / 设置 / 导出           │
├──────────────────────────────────────────────┤
│ 流程栏：项目概览 -> 数据导入 -> 数据检查 -> 测试解译 -> 成果输出 │
├──────────────┬──────────────────────┬────────┤
│ 左侧资源树    │ 中央工作区             │ 右侧参数 │
│ 项目资源      │ 地图/表格/曲线/结果     │ 按页面出现│
├──────────────┴──────────────────────┴────────┤
│ 底部：检查信息 / 运行日志 / 导出记录 / 审计记录   │
└──────────────────────────────────────────────┘
```

布局规则：

- 左侧资源树常驻，但可折叠。
- 顶部流程栏常驻，表示当前工作步骤。
- 中央工作区永远是主角。
- 右侧参数栏只在“测试解译”和“成果输出”默认出现。
- 项目概览、数据导入、数据检查页面不常驻右栏，避免挤压主区域。
- 底部日志区可折叠，默认显示最近状态。

```text
项目资源

├─ 场址地图
├─ 钻孔数据
│  ├─ CPT09
```

资源树只放数据对象和页面入口，不放第一版暂缓的基础分析模块。

## 五个核心页面

### 1. 项目概览

目标：让用户知道项目当前处于什么状态。

主要区域：

- 场址示意和坐标散点图
- 钻孔/CPTU数量卡片
- 数据完整率
- 错误/警告数量
- 流程进度
- 下一步建议
- 项目信息摘要

第一版地图：

- 不接真实地图底图。
- 使用坐标散点图显示 CPT09、CPT19、SCPT1。
- 支持项目范围多边形占位。
- 点击点位显示点位详情。

### 2. 数据导入

目标：把营口 CPTU Excel 数据导入系统。

主要区域：

- 文件选择区
- 字段匹配表
- 单位识别
- 数据预览表
- 导入设置
- 导入日志

第一版优先支持：

- `CPT09数据.xlsx`
- `CPT19数据.xlsx`
- `SCPT1数据.xlsx`
- 对应班报表元数据

### 3. 数据检查

目标：集中处理质量问题。

主要区域：

- 错误、警告、建议、通过统计
- 问题类型筛选
- 问题列表
- 问题详情
- 定位到数据
- 标记处理状态

第一版检查项：

- 坐标缺失
- 深度递增异常
- 深度范围与终孔深度不一致
- `qc/qt/U2/Fr` 缺失
- 摩阻比异常
- 孔压异常值
- 元数据缺失

### 4. 测试解译

目标：完成第一版 CPTU 解译和结果查看。

主要区域：

- 当前测点摘要
- 深度剖面曲线区
- 解译结果表
- 岩土参数表
- 右侧参数栏
- 运行日志

右侧参数栏：

- 解译方法
- 探头面积比
- 水重度
- 孔压修正
- 滤波窗口
- 土类识别方法
- 保存方案
- 方案对比

第一版计算边界：

- CPTU 使用 Mayne 公式子集。
- SPT 只做数据流、界面和结果结构。

### 5. 成果输出

目标：集中导出第一版勘察解译成果。

第一版真实导出：

- Excel 数据表
- 数据检查报告
- 计算日志
- 审计记录

第一版只做入口：

- DXF
- PDF

界面区域：

- 成果项选择
- 成果预览
- 导出设置
- 导出摘要
- 导出记录

## 控件选择

WinUI 控件优先级：

- Shell：`NavigationView`
- 顶部流程：自定义轻量 Stepper 或 `ItemsRepeater`
- 页面命令：`CommandBar`
- 表格：优先 DataGrid 方案，必要时引入 CommunityToolkit
- 参数：`NumberBox`、`ComboBox`、`ToggleSwitch`、`CheckBox`
- 状态提示：`InfoBar`
- 弹窗确认：`ContentDialog`
- 日志列表：`ListView`
- 页面标签：`TabView`

原则：

- 能用 WinUI 原生控件就不用自定义控件。
- 页面动作优先放 `CommandBar`。
- 不把普通按钮伪装成很多彩色标签。

## 响应式规则

宽屏：

- 左侧资源树 + 中央工作区 + 右侧参数栏。

中等宽度：

- 左侧资源树可折叠。
- 右侧参数栏改为浮层或折叠面板。

窄宽度：

- 页面变为单列。
- 流程栏可横向滚动或压缩为当前步骤。
- 日志区默认收起。

## 主题与材料

- 主窗口背景可使用 Mica。
- 弹出层、菜单可使用 Acrylic 或系统默认浮层材质。
- 支持浅色、深色、高对比度。
- 使用 theme-aware resource，不写死浅色背景。

## 自我审查

这个方案没有沿用原操作手册风格，也没有把参考图一比一复刻。参考图中有效的是五步流程、数据工作台密度、右侧参数按需出现；最终方案把记忆点放在 CPTU 深度剖面，这是从项目数据本身生成的识别特征。
