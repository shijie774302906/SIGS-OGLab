## 项目定位

本项目第一版不是复刻原系统的全部功能，也不是做完整基础设计计算软件，而是开发一个面向海上风电岩土勘察数据处理的现代桌面工作台。

已确认品牌与命名：

- 企业名：`SIGS-OGLab`
- 软件名：`海上风电岩土勘察解译`
- 内部英文项目名：`OffshoreGeotechWorkbench`
- 顶部栏建议显示：`SIGS-OGLab | 海上风电岩土勘察解译`
- 第一版不使用中国电建、原操作手册公司标识或参考图中的真实第三方 Logo。
- Logo 可设计为自制的海上风电/海洋岩土/地层解译符号。

第一版目标：

> 围绕“项目数据导入、质量检查、CPTU/SPT测试解译、岩土参数整理、勘察成果导出”形成闭环。

建议技术方向：

- 应用形态：Windows 桌面软件
- 技术栈：C# + WinUI 3 + Windows App SDK
- 默认存储：本地 SQLite 项目库
- 第一版重点：单机原型、数据工作台、勘察解译成果
- 暂缓方向：多用户 C/S、MySQL/Oracle、完整基础设计计算、国产化适配、安装包自动更新

已确认存储决策：

- 第一版只做本地 SQLite，不接入 MySQL/Oracle。
- 后续开发产生的项目库、导入缓存、导出记录、日志、样例数据副本和应用配置，默认都放在当前项目目录 `E:\CPT-software` 下。
- 不把应用数据写入微信原始文件目录、系统全局目录或用户不可见目录。
- 建议后续应用内数据目录为 `E:\CPT-software\app_data\`，用于存放 SQLite 数据库、导入副本、导出文件和日志。

## 第一版主流程

顶部流程压缩为 5 个主模块：

```text
项目概览 -> 数据导入 -> 数据检查 -> 测试解译 -> 成果输出
```

原先可能独立出现的“参数确认”不作为一级流程，而是并入“测试解译”内部，作为参数设置或子页签。

“基础分析”不进入第一版主流程。

## 产品闭环

第一版产品闭环定义为：

```text
新建项目
-> 导入钻孔 / CPTU / SPT / 室内试验数据
-> 数据检查与修正
-> CPTU / SPT 解译
-> 岩土参数整理
-> 综合柱状图 / 解译表 / 参数表导出
```

这个闭环能体现海洋岩土专业特色，同时避免第一版陷入完整基础设计规范计算。

## 公式来源与实现边界

用户已提供 `Mayne著作翻译.md` 作为第一版公式来源。已从该文件自动抽取两个公式索引：

- `Mayne_formula_index_initial.md`：Mayne 文档中的 CPT/CPTU 相关公式初筛索引，共 233 条候选公式
- `MVP_formula_candidates.md`：面向第一版测试解译的公式候选清单，共 100 条候选公式

初步判断：

- CPTU 真实计算可以从 Mayne 文档中提取公式逐步实现。
- 可优先实现：锥尖阻力修正、侧壁摩阻修正、孔压/有效应力、上覆应力、土重度估算、SBT/Ic土类识别、部分强度参数和岩土参数整理。
- SPT 在 Mayne 文档中有提及，但该文件主体是 CPT/CPTU，并不能确认完整覆盖 SPT 修正公式。
- 因此第一版建议采用“CPTU真实公式子集 + SPT界面/数据流优先 + SPT公式待补充来源”的策略。

已确认决策：

- 第一版接受上述策略。
- CPTU 解译优先实现 Mayne 文档覆盖的真实公式子集。
- SPT 第一版先实现界面、导入、检查、曲线/结果表展示和数据流。
- SPT 真实修正公式在补充明确公式来源后再接入计算引擎。

实现前必须把候选公式进一步整理成 `公式规格说明.md`，逐条明确：

- 公式编号和来源行号
- 输入变量
- 输出变量
- 单位要求
- 适用土类
- 参数默认值
- 边界条件
- 缺失值处理
- 验算样例

## 五个核心页面

### 1. 项目概览

用途：让用户快速知道项目当前状态。

主要内容：

- 项目场址示意
- 钻孔/CPTU坐标散点图
- 项目范围多边形
- 钻孔数量
- CPTU数量
- 数据完整率
- 错误/警告数量
- 下一步建议
- 项目信息摘要

已确认地图决策：

- 第一版不接入真实地图底图。
- 第一版实现“场址示意 + 坐标散点图 + 项目范围多边形 + 点位详情”。
- 不在第一版处理真实在线地图服务、离线瓦片地图、地图版权、坐标投影转换等复杂问题。
- 真实地图底图和坐标系转换放到后续阶段。

界面原则：

- 不显示常驻右侧参数栏
- 以状态卡片、地图、检查摘要为主
- 点击建议可跳转到对应流程页

### 2. 数据导入

用途：导入并预览勘察数据。

主要内容：

- Excel / CSV / CPTU 数据文件导入
- 钻孔数据模板下载
- 字段匹配
- 单位识别
- 数据预览
- 覆盖或新建钻孔判断
- 导入日志

来自操作手册的依据：

- 钻孔模板下载
- 钻孔导入
- 根据钻孔编号判断覆盖或新建
- 导入后自动更新属性表与工程管理节点

界面原则：

- 可以减少或不显示右侧参数栏
- 导入动作按步骤组织：选择文件、字段匹配、数据预览、检查并导入

### 3. 数据检查

用途：作为核心质量控制模块。

检查范围：

- 坐标缺失或坐标异常
- 深度区间范围错误
- 地层命名缺失或不规范
- CPTU异常点
- SPT数据缺失
- 单位问题
- 图层名称问题
- 输入异常、缺失项

主要内容：

- 问题统计卡片
- 问题列表
- 问题详情
- 建议处理方式
- 定位到数据
- 应用修复或忽略问题
- 检查历史

界面原则：

- 右侧详情面板可按需出现
- 中央区域优先给问题表格和筛选器

### 4. 测试解译

用途：第一版最核心的专业页面。

主要内容：

- CPTU曲线
- SPT曲线
- 分层柱状图
- 解译方法选择
- 参数设置
- CPTU参数
- SPT修正参数
- 解译结果表
- 运行解译
- 保存方案
- 方案对比

来自操作手册的依据：

- SPT修正
- CPTU参数设置
- CPTU分析
- 综合柱状图
- CPTU结果导出
- 岩土参数整理

界面原则：

- 右侧参数栏在此页面打开
- 参数确认作为该页面内部子页签或折叠面板
- 中央区域以曲线、柱状图和结果表为主

### 5. 成果输出

用途：输出勘察解译成果，不输出基础设计成果。

第一版输出内容：

- 综合柱状图
- CPTU解译成果表
- SPT修正成果表
- 岩土参数汇总表
- 数据检查报告
- 计算日志 / 审计记录
- Excel / DXF / PDF

已确认决策：

- 第一版真实实现 Excel 数据导出。
- 第一版真实实现数据检查报告、计算日志/审计记录导出。
- DXF 和 PDF 第一版先做导出中心入口、成果项选择、预览占位和导出记录。
- DXF 和 PDF 的真实文件生成放到第二阶段，待图件规范、报告模板和排版要求确认后实现。

来自操作手册的依据：

- 综合柱状图
- 无CPT柱状图
- DXF导出
- CPTU解译结果导出
- 属性表Excel导出

界面原则：

- 右侧导出设置面板可打开
- 中央区域展示成果项、预览和导出记录
