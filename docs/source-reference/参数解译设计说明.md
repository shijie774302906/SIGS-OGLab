## 3. Formula Source Review

### 3.1 Drained friction angle for sands and silty sands

Preferred first implementation:

```text
φ'_p = 17.6° + 11.0 log10(Qtn)
```

Source:

- `Mayne_formula_index_initial.md`, F108 line 1946, Eq. 5.6
- `Mayne著作翻译.md`, Eq. 5.6

Applicability:

- drained behavior range from the local Mayne source: `IcRW < 2.6`
- requires `Qtn > 0`
- output unit: degrees
- intended for sands and silty sands

Current-app normalization rule:

- the current persisted `Ic` is computed by the first-pass Robertson-Wride style `Ic` formula recorded in `公式规格说明.md`, using `Qtn` and `Fr`.
- for Slice 6B/6C applicability only, this current first-pass `Ic` is treated as the app's `IcRW` gate.
- UI wording should say `按当前首轮 Ic 判定适用性`, not imply that a separate laboratory or SBT12 classification has been performed.
- threshold is strict: `Ic < 2.60` is drained/sand-like applicability for the first `φ'` curve; `Ic >= 2.60` is not applicable for this `φ'` method.
- missing or non-computable `Ic` makes the parameter row invalid for both first-pass applicability decisions.

Implementation rule:

- compute this as the primary first-pass `φ'` curve only for drained/sand-like rows.
- do not compute a fake `φ'` value for clay-like rows from this formula.
- record invalid reasons separately: missing `Qtn`, non-positive `Qtn`, non-drained row, or undefined `Ic`.

Optional cross-check, not primary output:

```text
φ'_p = 53° - 6.9 IcRW
```

Source:

- `Mayne_formula_index_initial.md`, F109 line 1958, Eq. 5.7

Use:

- can be shown later as a comparison method or QA check.
- should not replace the Qtn-based primary curve in the first implementation.

### 3.2 Clay friction angle from NTH solution

Candidate formula:

```text
φ'_p = 29.5° * Bq ^ [0.121(0.256 + 0.336 Bq + log Q)]
```

Source:

- `Mayne_formula_index_initial.md`, F112 line 2032, Eq. 5.10

Applicability:

- soft to firm clays
- `OCR < 2.5`
- `20° <= φ'_p <= 45°`
- `0.1 <= Bq <= 1.0`
- requires `Q` and `Bq`

Decision:

- defer this method from the first code slice.
- reason: the current formal run does not yet expose a reviewed `Bq`/`Q` workflow or OCR condition for this method.
- it can become a later pluggable method after `Bq`, pore pressure baseline, and OCR/applicability checks are designed.

### 3.3 Undrained shear strength from cone factor

Preferred first implementation:

```text
Su = (qt - sigma_v0) / Nkt
Su = qnet / Nkt
```

Source:

- `Mayne_formula_index_initial.md`, F124 line 2404, Eq. 6.7
- source text records `Nkt` commonly in the range `10-20` for soft intact clays
- source text records offshore soft-to-firm clay recommendations near `Nkt = 12` for triaxial compression mode

Applicability:

- undrained/clay-like interpretation only
- requires `qnet > 0`
- requires a declared `Nkt`
- output unit: kPa
- first implementation uses the same current-app applicability gate: `Ic >= 2.60` for undrained/clay-like rows; `Ic < 2.60` is not applicable for this `Su` method.

Implementation rule:

- default `Nkt = 12` can be offered as a first-pass offshore clay estimate, but it must be visible as a method parameter.
- the UI must say this is an empirical cone-factor estimate, not a lab-calibrated design strength.
- rows outside clay-like/undrained applicability should remain blank or marked not applicable, not forced to zero.
- invalid reasons must be counted: missing `qnet`, non-positive `qnet`, non-clay-like row, missing/invalid `Nkt`.

### 3.4 Pore-pressure and effective-cone Su methods

Candidate formulas:

```text
Su = (u2 - u0) / N_delta_u
Su = (qt - u2) / NkE
```

Source:

- `Mayne_formula_index_initial.md`, F125 line 2434, Eq. 6.8
- `Mayne_formula_index_initial.md`, F126 line 2454, Eq. 6.9

Decision:

- defer from the first implementation.
- reason: they require separate pore-pressure factor choices and stronger method labeling. They are useful later as alternative methods in the same pluggable framework.

## 4. General Method Model

Do not hard-code the UI to one method as the only future path.

Recommended structure:

- `InterpretationMethodCatalog`: method definitions and display metadata
- method kind: classification, chart, parameter interpretation, export, future foundation module
- parameter derivation service: computes parameter series from the latest run and raw rows
- method parameter object: stores visible defaults such as `Nkt`
- applicability policy: decides which rows can receive each parameter
- invalid reason model: explains why a row has no value

First parameter method IDs:

- `CPTU-Param-PhiSand-Qtn-Mayne`
- `CPTU-Param-Su-Nkt-MayneLunne`

These IDs are internal identifiers. Visible UI should show Chinese names with method IDs only as secondary metadata.

## 5. Persistence Policy

Current database already has `SuKpa` and `PhiDeg`, but no per-parameter method provenance.

Recommended staged policy:

1. First code slice can compute parameter curves from the latest run as a derived view.
2. Do not export or present these values as final persisted design parameters until method provenance is explicit.
3. If persistence is needed, add or reuse a clear provenance route before writing non-null `SuKpa` and `PhiDeg`:
   - method ID
   - method version
   - parameter JSON, including `Nkt`
   - applicability thresholds
   - invalid counts
4. Do not overwrite the existing `CPTU-RW-Ic-FirstPass` classification logic when adding parameter results.

## 6. UI Layout Design

Add `参数解译` only after the first real parameter computation exists.

Recommended tab order:

```text
曲线剖面 | SBT 12区图 | 参数解译 | 分层参数 | 计算日志
```

Center layout:

```text
┌───────────────────────────────────────────────┬─────────────────────┐
│ 参数曲线                                      │ 方法与适用性说明     │
│                                               │                     │
│ φ' 曲线，深度向下                             │ φ' 方法、公式、范围  │
│ Su 曲线，深度向下                             │ Su 方法、Nkt、范围   │
│ 缺失/不适用区段断开显示                       │ 无效/不适用统计      │
└───────────────────────────────────────────────┴─────────────────────┘
```

Curve requirements:

- share the same depth axis as `CPTU 曲线剖面`
- `φ'` track unit: degree
- `Su` track unit: kPa
- non-applicable values are gaps, not zero lines
- selected left depth/layer should highlight corresponding curve interval
- chart legend must separate `φ'` and `Su` colors clearly
- use nature-like, low-saturation colors on white plotting surfaces

Right explanation panel:

- show formula with readable subscripts where practical
- show `Nkt` value and whether it is default or user-edited
- show applicability counts:
  - valid `φ'`
  - valid `Su`
  - non-applicable rows
  - invalid input rows
- state that SBT12 is not used to determine sand/clay for these first curves; first-pass `Ic` applicability is used until a source-reviewed replacement exists.

Text and typography:

- Chinese-first labels
- method IDs only as small secondary text
- no long English status sentences
- no crowded formula blocks
- no grey-heavy background

Interaction:

- left depth/layer selection should highlight parameter-curve intervals.
- clicking parameter-curve points does not need to drive left layer selection in the first implementation.
- no empty placeholder tab should be visible before real computation exists.
