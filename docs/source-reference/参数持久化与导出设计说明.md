# 参数持久化与导出设计说明

Date: 2026-06-23

Scope:

- page: `测试解译`
- module: CPTU parameter interpretation
- parameters covered in the first design: `φ'` and `Su`
- current stage: Slice 6F parameter export workbook implemented and audited; next refinement is stale-run warning/responsive evidence if confirmed.

This document records the Slice 6D decision for whether and how `SuKpa` and `PhiDeg` can become persistent/exportable engineering results.

## 1. Grill-Me Decision Tree

### Q1: Should Slice 6D immediately write `SuKpa` and `PhiDeg` into `InterpretationResults`?

Recommended answer:

- No.

Reason from current code:

- `InterpretationResults` already has value columns `SuKpa` and `PhiDeg`.
- `CptuInterpretationService.InsertResults` deliberately writes both as `NULL`.
- `interpretcheckrun` currently verifies that the Slice 6B/6C derived view leaves these columns `NULL`.
- There is no per-parameter method ID, method version, visible parameter JSON, applicability threshold, status, invalid reason, or source-run provenance attached to those two columns.

Decision:

- Do not write non-null `SuKpa` or `PhiDeg` into `InterpretationResults` in the next implementation slice.
- Treat those existing columns as legacy/reserved convenience fields until a formal selected-parameter-result contract exists.

### Q2: Where should persistent parameter results live?

Recommended answer:

- Use separate parameter interpretation tables rather than widening `InterpretationResults` with more columns.

Reason:

- `φ'` and `Su` can use different methods and method parameters in the same visible view.
- Future methods will add `OCR`, `Dr`, alternative `Su`, clay `φ'`, pore-pressure methods, and foundation inputs.
- A long-form value table can store one parameter-method result per depth interval without schema churn.

Decision:

- Add a future `ParameterInterpretationRuns` table for each saved parameter run.
- Add a future `ParameterInterpretationValues` table for per-depth, per-parameter values and status.

### Q3: Should parameter export be added to the existing first-pass workbook immediately?

Recommended answer:

- Not until persistent parameter provenance exists.

Reason from current code:

- `CptuExportService` exports the latest completed first-pass `CPTU-RW-Ic-FirstPass` run.
- The current workbook sheets are `Summary`, `Parameters`, and `Results`.
- `Results` exports first-pass fields only: depth, soil type, `Ic`, `qt`, stresses, `qnet`, `Fr`, `Qtn`, and `γ`.
- Adding `φ'` and `Su` columns without a method/provenance sheet would make the workbook look like a formal parameter deliverable while hiding method status and invalid reasons.

Decision:

- Keep the existing first-pass workbook unchanged until persistent parameter runs exist.
- Add a separate future `ParameterInterpretation-Xlsx` export or add clearly named parameter sheets only after provenance is persisted.

### Q4: Should editing `Nkt` automatically persist results?

Recommended answer:

- No.

Reason:

- `Nkt` is a method parameter and may be exploratory.
- Automatic writes would create durable engineering outputs from every UI tweak.

Decision:

- `Nkt` edits continue to refresh the derived view only.
- A future explicit command such as `保存参数解译` can create a parameter run after the user accepts method settings.

  - `MethodName`
  - `ParameterJson`
  - `StartedAt`
  - `FinishedAt`
  - `Status`
- `InterpretationResults`
  - first-pass result fields
  - reserved `SuKpa`
  - reserved `PhiDeg`
  - no per-parameter method/status/reason fields
- `ExportRecords`
  - export metadata only

Current write path:

- `CptuInterpretationService.RunFirstPass`
- `InsertRun` writes a `CPTU-RW-Ic-FirstPass` run and first-pass settings.
- `InsertResults` writes `SuKpa=NULL` and `PhiDeg=NULL`.

Current derived path:

- `CptuParameterInterpretationService` computes derived `φ'` and `Su` from the latest completed first-pass run.
- The Slice 6C UI shows those values as a derived, non-persisted view.

Current export path:

- `CptuExportService.ExportLatestInterpretationWorkbook`
- exports the latest first-pass run only.
- current workbook does not export parameter interpretation values.

## 3. Required Provenance Contract

Any persistent parameter value must be traceable to:

- project ID
- test point ID
- source first-pass interpretation run ID
- source first-pass method name
- source depth interval or source result row ID
- parameter key:
  - `PhiDeg`
  - `SuKpa`
- display name
- unit
- method ID
- method version
- formula reference
- method parameter JSON:
  - for `Su`: `Nkt`
  - for `φ'`: current `IcApplicabilityThreshold`
- applicability threshold JSON
- source input summary:
  - `Ic`
  - `Qtn`
  - `qnet`
  - optional future inputs such as `Bq`, `OCR`, `u0`, or lab calibration reference
- value
- status:
  - `Valid`
  - `NotApplicable`
  - `InvalidInput`
  - `InvalidMethodParameter`
- reason code
- created time
- software/app method contract version

## 4. Proposed Future Schema

### 4.1 `ParameterInterpretationRuns`

Purpose:

- one explicit saved parameter-interpretation run for a test point and source first-pass run.

Columns:

```text
Id INTEGER PRIMARY KEY AUTOINCREMENT
ProjectId TEXT NOT NULL
TestPointId TEXT NOT NULL
SourceInterpretationRunId INTEGER NOT NULL
RunLabel TEXT
MethodSetId TEXT NOT NULL
MethodSetVersion TEXT NOT NULL
ParameterJson TEXT NOT NULL
SummaryJson TEXT NOT NULL
StartedAt TEXT NOT NULL
FinishedAt TEXT
Status TEXT NOT NULL
CreatedBy TEXT
Notes TEXT
```

Foreign keys:

```text
ProjectId -> Projects.Id ON DELETE CASCADE
TestPointId -> TestPoints.Id ON DELETE CASCADE
SourceInterpretationRunId -> InterpretationRuns.Id ON DELETE RESTRICT
```

Minimum indexes:

```text
IX_ParameterInterpretationRuns_ProjectPoint
IX_ParameterInterpretationRuns_SourceRun
```

### 4.2 `ParameterInterpretationValues`

Purpose:

- long-form per-depth, per-parameter records.

Columns:

```text
Id INTEGER PRIMARY KEY AUTOINCREMENT
ParameterRunId INTEGER NOT NULL
SourceResultId INTEGER
DepthFrom REAL NOT NULL
DepthTo REAL NOT NULL
ParameterKey TEXT NOT NULL
DisplayName TEXT NOT NULL
Unit TEXT NOT NULL
Value REAL
Status TEXT NOT NULL
ReasonCode TEXT NOT NULL
MethodId TEXT NOT NULL
MethodVersion TEXT NOT NULL
FormulaRef TEXT NOT NULL
MethodParameterJson TEXT NOT NULL
ApplicabilityJson TEXT NOT NULL
SourceInputJson TEXT NOT NULL
```

Foreign keys:

```text
ParameterRunId -> ParameterInterpretationRuns.Id ON DELETE CASCADE
SourceResultId -> InterpretationResults.Id ON DELETE SET NULL
```

Minimum indexes:

```text
IX_ParameterInterpretationValues_RunDepth
IX_ParameterInterpretationValues_RunParameter
IX_ParameterInterpretationValues_Status
```

Rule:

- `Value` may be non-null only when `Status='Valid'`.
- invalid and non-applicable rows must still be stored with `Value=NULL` and a reason code.
- Slice 6E should prefer carrying `InterpretationResults.Id` through the derived source-row model and saving it as `SourceResultId`.
- If `SourceResultId` cannot be available in the first implementation, the fallback provenance key is `SourceInterpretationRunId + DepthFrom + DepthTo + ParameterKey`, and this fallback must be documented in the process log.

Duplicate handling:

- Saving the same source run and same method settings should create a new auditable parameter run by default, not silently overwrite the prior run.
- A later `replace previous run` command may be added, but it must be explicit and must preserve the old run unless the user deliberately deletes it.

Transaction rule:

- Save the parameter run and all parameter values in one database transaction.
- If any value insert fails, roll back the run row and leave the UI in derived-view state.

## 5. Existing `SuKpa` and `PhiDeg` Columns

Decision:

- Keep `InterpretationResults.SuKpa` and `InterpretationResults.PhiDeg` nullable and unused in the immediate next implementation.

Allowed future use:

- They may be populated only from an explicitly selected saved `ParameterInterpretationRun`.
- If populated later, the selected parameter run ID must be recorded so the bare value columns are not orphaned.

Rejected use:

- Do not write derived-view values directly during first-pass `RunFirstPass`.
- Do not write values automatically when the user edits `Nkt`.
- Do not export these columns as final values without a provenance sheet.

## 7. UI Contract For Persistence

Future UI should not save silently.

Recommended command:

```text
保存参数解译
```

Before saving, show:

- source first-pass run ID
- selected method set
- `Nkt`
- `Ic` applicability threshold
- valid/not-applicable/invalid counts
- non-persistence warning changing to a save confirmation

After saving, show:

- parameter run ID
- saved time
- current export availability
- whether this saved run is selected for export
