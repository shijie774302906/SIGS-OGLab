# 界面布局排版规范

Date: 2026-06-22

Scope:

- `SIGS-OGLab | 海上风电岩土勘察解译`
- Windows desktop engineering workbench UI
- Current priority page: `测试解译`

## 1. Core Direction

The app is a Chinese engineering interpretation tool. UI language must be Chinese by default.

Allowed non-Chinese text:

- engineering symbols and formula variables, such as `CPTU`, `SBTn`, `Ic`, `Qtn`, `Fr`, `qt`, `qc`, `u2`
- units, such as `m`, `kPa`, `MPa`, `kN/m3`
- persisted method codes when they are shown as identifiers, but they should be paired with a Chinese method name when visible

Disallowed in user-facing UI:

- English status sentences such as `Latest run`, `Ready to run`, `Point`, `Records`, `Attachments`
- English soil class labels such as `Sand-like`, `Clay-like`, `Transitional`, `Undefined`
- English chart descriptions unless they are formula notation

## 2. Layout Rules

The interpretation page should read as one workbench, not separate stacked cards.

Wide desktop order:

```text
left rail: point / formula / layer index
center: result tabs and dominant curve or active result
right rail: method / parameters / run status / attachments lower
```

Priority:

1. `曲线剖面` is the primary evidence view and must not look like a thumbnail.
2. `SBT 12区图` is the current active SBT chart target and must explain source, axes, auxiliary status, and limits.
3. Historical `SBTn 图` rules apply only when SBTn work is explicitly resumed.
4. `分层参数` must use available vertical space to show enough rows; avoid a small table floating in a large blank area.
5. `计算日志` must summarize real available state only; do not imply scheme comparison or SPT logs are implemented.

## 3. Visual System

The user does not like grey-heavy UI.

Use the fixed color system below. Future UI work should not invent local greys or one-off panel colors unless the deviation is recorded in `process_logs/Process*.md`.

| Role | Token | Hex | Use |
| --- | --- | --- | --- |
| App background | `WorkbenchAppBackground` | `#F6FBFF` | main window/page background, replacing default grey page fill |
| Navigation background | `WorkbenchNavigationBackground` | `#F9FDFF` | workflow rail and shell side areas |
| Primary surface | `WorkbenchSurface` | `#FFFFFF` | cards, workbench panels, tables, form panels |
| Secondary surface | `WorkbenchSurfaceAlt` | `#F2F8FC` | subtle grouped blocks only; never large grey cards |
| Border/divider | `WorkbenchLine` | `#D7E6EF` | borders, grid lines, separators |
| Primary text | `WorkbenchTextPrimary` | `#17212B` | headings and main labels |
| Secondary text | `WorkbenchTextSecondary` | `#5C6B75` | hints, notes, metadata |
| Primary action | `WorkbenchBlue` | `#0B63CE` | selected state, primary action, `qt` curve |
| Soft blue selected fill | `WorkbenchBlueSoft` | `#EAF4FF` | selected navigation/item background |
| Green | `WorkbenchGreen` | `#1F9D55` | available/pass state, `fs` curve |
| Violet | `WorkbenchViolet` | `#754BF7` | `u2`, Ic/SBTn-related accent |
| Orange | `WorkbenchOrange` | `#F4A01D` | sand/warning/accent |
| Neutral unavailable | `WorkbenchNeutral` | `#C7D0DA` | undefined/unavailable only |

Use:

- base background: `WorkbenchAppBackground`
- primary surfaces: `WorkbenchSurface`
- secondary grouping: `WorkbenchSurfaceAlt`
- dividers and strokes: `WorkbenchLine`
- selected/active state: `WorkbenchBlue` plus `WorkbenchBlueSoft`
- status/chart semantics: fixed green, violet, orange, and neutral tokens above

Avoid:

- large grey panels
- grey cards nested inside grey cards
- decorative gradients, orbs, or marketing-style hero blocks
- shrinking the main curve just to reveal secondary content
- direct use of WinUI grey-heavy resources such as `ControlAltFillColorSecondaryBrush` for large page or card surfaces

## 4. Formula Presentation

Formula text must use proper subscripts where practical.

Required style:

```text
qt = qc + (1 - anet) u2
qnet = qt - sigma'v0
Fr = 100 fs / qnet
```

In the UI, variables should be rendered with subscript text instead of plain `a_net`, `σv0`, or `u2` when the control supports it.

## 5. Chart Rules

`曲线剖面`:

- use the available center width
- keep depth-aligned tracks readable
- use Chinese legend labels such as `qt 解译`, `qc 原始`, `fs 原始`, `u2 原始`, `Ic`

`SBT 12区图`:

- use a white plotting area
- use the Excel-backed `FR = fs/qt (%)` linear x-axis from `0` to `8`
- use the Excel-backed `qt (bar)` log10 y-axis from `1` to `1000`
- draw multi-color boundary lines from the extracted Excel curve data
- explain that SBT12 is auxiliary interpretation and does not replace the formal first-pass `Ic` classification
- use low-saturation point colors and a stronger selected-depth highlight
- keep one-way linkage from left depth/layer selection to chart-point highlight
- do not let clicking chart points change the left depth/layer selection

Historical `SBTn 图`:

- explain that the plot is a Qtn-Fr distribution on log axes
- explain that point colors follow the current Ic/SBTn soil classification
- state honestly that Robertson 9-zone boundaries are not included in the current MVP
- do not leave the user with a chart whose meaning is only implied by an English axis title

## 6. Table Rules

`分层参数表` should be dense but readable.

Required behavior:

- show more rows when the tab is active
- keep selected layer linked with the left layer index
- show Chinese soil class labels
- avoid large blank center space caused by a too-small `MaxHeight`

## 7. Future UI Change Gate

Before changing layout or visible text:

1. check this file
2. preserve Chinese-first UI language
3. preserve curve-first interpretation priority
4. avoid grey-heavy surfaces
5. capture screenshot evidence for visual review
6. record any intentional deviation in the active `process_logs/Process*.md`

## 8. Screenshot Review Requirement

Layout and visual-design work must be reviewed from screenshots, not only from source code or UI Automation.

Minimum screenshot set:

- target wide desktop view for the changed page
- the active result tab or workflow state being changed
- the relevant reference image or user screenshot placed in the audit context

When responsiveness is part of the change, also capture:

- medium-width layout
- narrow layout
- any scrolled state needed to prove content reachability

The screenshot review must answer these questions:

- Does the page visually match the approved direction better than before?
- Is the main engineering evidence, especially `曲线剖面`, visually dominant enough?
- Does the screen still feel like scattered cards or a coherent workbench?
- Are there large empty areas that could hold useful content?
- Are labels, legends, formulas, tables, and chart notes readable without crowding?
- Is the background light and intentional rather than grey-heavy?
- Are any controls, labels, or chart elements clipped, overlapping, or truncated in a way that harms understanding?

Audit agents must receive the screenshots and the reference image path. A design/layout audit that only reads XAML, C# source, or UIA output is incomplete.
