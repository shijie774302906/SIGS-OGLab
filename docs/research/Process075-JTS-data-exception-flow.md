# Process075 - JTS 数据异常处理 Flow 调研

Date: 2026-07-12

Status: `research complete / awaiting product confirmation`

## 1. 结论先行

当前问题不是缺少一个“忽略”按钮，而是分类结果、异常证据、数据治理和分层方案四个对象被挤在同一个右侧面板里，用户无法判断按钮会改变什么。

推荐改成两层交互：

1. **短决策弹窗**：分类完成后只问一次“这些异常点怎么处理？”，给出系统推荐、影响范围和最多两个替代入口。
2. **完整异常审查工作区**：只有用户选择查看详情时才进入；中心并列显示 qc、fs、u2，共享深度轴，右侧负责区间选择和批量操作。

“忽略”应成为正式选项，但语义必须是：**原始数据保留，只在本次候选方案中不让这些测量点参与分类和边界生成**。忽略必须可预览、可撤销、可追溯，不能等同于删除或把数值改成空值。

## 2. 当前 Flow 的主要问题

1. `标准平滑并重新分类` 既是处理动作又像继续动作；处理后仍有问题时会再次出现同一个按钮，形成循环。
2. `处理完成` 与 `需要先处理` 同时出现，用户不知道“完成”的是平滑、检查还是分类。
3. 重新分类只更新分类运行，不更新只读分层方案，但页面没有明确说明对象边界。
4. 右侧只显示行数和分类统计，没有在决策时提供 qc、fs、u2 的共同深度证据。
5. 目前以“异常行百分比”为主要继续条件；对高频 CPTU 数据，更重要的是异常是否孤立、连续厚度、分布区间和三通道是否共同异常。
6. 高级控制展开后仍以指标和按钮为主，不能完成逐点或逐区间审查。
7. 现有中心曲线只绘制 qc；用户无法判断异常是单通道尖峰、孔压独有问题，还是多通道共同变化。

### 3.2 不应照搬

- 不采用 Bonsai 式整页错误墙；数百条逐行错误会再次制造当前问题。
- 不把 Copy.ai 的完整数据表直接塞进普通弹窗；工程曲线需要持续的深度上下文和足够宽度。
- 不采用“永久忽略”作为默认选项。CPTU 忽略必须绑定分类运行和候选方案，并允许恢复。
- 不把 qc、fs、u2 画在同一数值轴上。三者单位和幅值差异很大，应使用共享深度轴的并列小图。
- 不复制竞品视觉；只借鉴信息层级、作用域说明、结果摘要和撤销模式。

## 4. 推荐信息架构

### 页面默认状态

- 中心顶部：分类是否完成、当前只读方案是否变化。
- 中心证据：qc、fs、u2 三轨共享深度轴，异常区间横向贯穿三轨。
- 右侧功能坞：分类运行状态、已选处理策略、重新打开决策弹窗、高级审查入口。
- 弹窗：只在分类完成、发现需要用户决策的异常时出现。

### 三轨证据设计

```text
共享深度       qc / qt             fs                 u2              分类/边界
 0.01 m   ┌────────────┐    ┌────────────┐    ┌────────────┐    ┌──────────┐
          │   原始曲线  │    │   原始曲线  │    │   原始曲线  │    │   Zone   │
 12.16 m  │████异常带████│    │████异常带████│    │████异常带████│    │ 候选边界 │
          │ 处理后虚线  │    │ 处理后虚线  │    │ 处理后虚线  │    │ 当前边界 │
 60.76 m  └────────────┘    └────────────┘    └────────────┘    └──────────┘
```

- 每条曲线使用自己的横轴和单位，但共享纵向深度、缩放、悬停十字线和选中区间。
- 点击右侧异常区间，四个轨道同时缩放到相同深度范围。
- 原始值使用实线；平滑试算使用虚线；忽略点使用灰色空心标记；缺失通道显示斜线空带，不画成 0。
- 单通道异常只高亮对应轨道，多通道异常使用贯穿所有轨道的淡色深度带。
- 默认显示异常上下各一段上下文，并提供 `查看全孔`；不要一次展示几千行表格。

## 5. 推荐决策弹窗

```text
┌──────────────────────────────────────────────────────────┐
│ 分类完成，但发现少量异常点                          ×   │
│ 148 个测量点 · 合并为 6 个深度区间 · 当前方案未改变      │
│                                                          │
│ [三轨迷你预览：qc | fs | u2，共享深度异常带]              │
│                                                          │
│ 系统建议                                                  │
│ ● 忽略这些异常点并建立候选方案                            │
│   原始数据保留；仅本次候选方案不使用这些点。              │
│                                                          │
│ ○ 自动处理后重新判断        （只在尚未执行且安全时出现）   │
│ ○ 查看异常详情                                            │
│                                                          │
│ [暂不采用本次分类]              [忽略 148 点并建立候选方案]│
└──────────────────────────────────────────────────────────┘
```

弹窗必须动态裁剪选项：

- 孤立、短区间且上下分类稳定：推荐忽略。
- 明确单点尖峰且标准平滑有安全预览：推荐自动处理。
- 孔压图域外但 Ic 有效：推荐只在受影响区间使用 Ic。
- 水深/压力基准未确认：只推荐修正上下文，不提供忽略。
- 连续厚区间、重大双路径冲突或忽略会改变关键边界：禁用忽略，推荐查看详情。
- 已自动处理一次但仍有问题：不再显示同一个自动处理按钮。

## 6. 推荐 Flow

```text
运行分类
   │
   ├─ 无需用户决定 ──> “分类完成”确认 ──> 建立新候选方案 / 暂不应用
   │
   └─ 发现异常 ──> 异常决策弹窗
                     │
                     ├─ 忽略并继续 ──> 影响预览确认 ──> 新候选方案 + 可撤销反馈
                     │
                     ├─ 自动处理 ──> 保存治理修订 ──> 重新检查/分类
                     │                                      │
                     │                                      └─ 仍有异常：回到决策弹窗，禁止重复同一处理
                     │
                     ├─ 查看详情 ──> qc/fs/u2 异常审查工作区
                     │                    ├─ 忽略所选
                     │                    ├─ 恢复所选
                     │                    ├─ 使用 Ic（适用区间）
                     │                    └─ 返回决策弹窗
                     │
                     └─ 暂不采用 ──> 保留分类运行，不改变当前方案
```

## 7. “忽略”对象与安全语义

忽略记录至少应冻结：

- 分类运行 ID、检查运行 ID和候选方案 ID。
- 受影响的 sourceRowId、深度区间和三通道原始值引用。
- 忽略原因：系统建议 / 用户选择 / 用户补充说明。
- 忽略前后的候选边界数量和受影响边界。
- 操作时间、恢复状态和后续陈旧原因。

忽略后：

- 原始行仍可查看和导出。
- 曲线上仍显示为空心点，而不是消失。
- 本次候选生成跳过这些点；是否跨过空缺连接上下分类必须由安全规则决定。
- 提供 `撤销忽略`，撤销后使对应候选方案陈旧并要求重新生成。
- 上游数据、探头或压力上下文变化后，旧忽略决定保留为历史，不自动应用到新运行。

## 8. 不能只用行数百分比决定

是否允许忽略至少需要共同考虑：

- 异常行占比。
- 合并后的物理深度厚度，而不是只看采样行数。
- 连续异常最大长度和异常区间数量。
- qc、fs、u2 是单通道异常还是共同变化。
- 异常上下的分类是否稳定一致。
- 是否靠近原始/建议边界。
- 忽略前后候选边界是否发生重大变化。
- 问题是否来自未确认的工程上下文；上下文问题不能用忽略绕过。

具体安全阈值属于后续实施切片，需要通过真实营口样例和工程确认冻结；本次调研不替代该决策。

## 9. 状态与文案

| 状态 | 默认标题 | 主操作 | 不应出现 |
| --- | --- | --- | --- |
| 分类完成、无异常 | 分类已完成，当前方案尚未改变 | 建立候选方案 | 处理完成 |
| 少量异常可忽略 | 发现少量异常点 | 忽略并建立候选方案 | 需要先处理 |
| 可自动处理 | 发现可自动处理的尖峰 | 预览处理结果 | 无预览的重新分类 |
| 自动处理后仍异常 | 处理已完成，仍有异常点需要选择 | 忽略或查看详情 | 再次显示同一个处理按钮 |
| 忽略不安全 | 这些异常可能影响地层边界 | 查看异常详情 | 忽略并继续 |
| 用户暂不采用 | 本次分类已保留，当前方案未改变 | 重新打开决策 | 分类失败 |
| 已建立候选 | 已建立新的候选方案 | 查看候选方案 | 暗示替换只读方案 |

## 10. 建议实施拆分

建议不要一次重写全部 Flow，分为三个可验收切片：

1. **异常决策与忽略修订**：新状态机、短弹窗、避免重复自动处理、忽略留痕和撤销。
2. **qc/fs/u2 联动证据**：共享深度三轨、异常带、缩放定位、缺失/忽略/平滑视觉状态。
3. **完整异常审查工作区**：区间列表、逐点选择、批量忽略/恢复、候选影响预览。

实施前需要用户确认：

- 默认忽略是否只绑定“本次候选方案”。
- 允许忽略的工程安全条件由谁确认。
- 自动处理后仍异常时，是否允许用户在明确警告下继续。
- 现有只读方案与新候选方案始终并存，还是允许显式替换。

- [Power Query - 处理单元格错误](https://learn.microsoft.com/zh-cn/power-query/dealing-with-errors)：单元格错误不会阻止整个查询加载，并提供移除、替换或保留错误的不同操作。

- [Airtable - CSV Import Extension](https://support.airtable.com/docs/csv-import-extension)：可跳过空白或无效 CSV 值，并保留恢复快照能力。
- [Sentry - Issue Status](https://docs.sentry.io/product/issues/states-triage/)：归档不会删除事件，可按升级、时间、次数或受影响用户恢复，强调忽略的作用域和可恢复性。
- [Datadog - Scoping Downtime](https://docs.datadoghq.com/monitors/guide/scoping_downtimes/)：先选择目标，再预览受影响对象，避免无范围的全局静默。
