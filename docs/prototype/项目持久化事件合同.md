# 项目持久化事件合同

Date: 2026-07-10

Status: `localStorage transport implemented / verified`

## 1. Purpose

Define how the browser prototype preserves and restores multiple project workspaces without confusing browser continuity with a formal engineering database.

This contract separates two concerns:

```text
ProjectCollectionState <-> versioned snapshot <-> storage transport
```

The versioned snapshot is shared by every transport. The transport remains an explicit product decision:

- browser `localStorage`
- downloadable/importable workspace file
- backend/database
- session-only memory

## 2. Persisted Object

The snapshot contains:

- project collection
- active project ID
- each project's import draft and version
- selected field and return focus
- check run ID, checked draft version, and check history
- selected filters and workflow selections
- project feedback and timestamps

The snapshot does not contain:

- browser functions, DOM nodes, `File` objects, object URLs, or transient toasts
- formal formulas or calculated engineering authority
- desktop database IDs beyond ordinary prototype strings
- export files or backend credentials

## 3. Schema

```json
{
  "schema": "sigs-oglab.project-collection",
  "version": 1,
  "savedAt": "2026-07-10T00:00:00.000Z",
  "state": {
    "projects": [],
    "activeProjectId": null
  }
}
```

Rules:

- Schema and version are mandatory.
- Project IDs must be unique.
- Every nested project, Flow case, import draft, check history, and workflow selection must pass validation.
- An unknown active project ID recovers to the project hub instead of invalidating valid projects.
- Unsupported versions are never silently coerced.

## 5. Storage Adapter Requirements

Whichever transport is selected must provide:

- `load(): DecodeResult`
- `save(state): SaveResult`
- `clear(): ClearResult`
- explicit error classification
- no mutation of the in-memory state on failure

For `localStorage`, the recommended additional rules are:

- use one namespaced key
- isolate Flow/test query sessions from saved user projects
- save only after state initialization
- recover invalid data without white-screening
- expose an explicit clear action with confirmation
- never describe browser storage as a formal database

## 6. Acceptance Flow For A Future Adapter

Playwright must prove:

1. Create two projects with different workflow states.
2. Refresh and restore both projects.
3. Open each project and verify its independent state.
4. Rename and delete, refresh, and verify the changes persist.
5. Inject malformed data and verify safe recovery without a page error.
6. Inject an unsupported version and verify explicit recovery state.
7. Open deterministic Flow/test URL and prove it does not overwrite saved user projects.
8. Clear saved projects through a confirmation action and verify the empty hub after refresh.

## 7. Implemented Decision

The current browser prototype uses versioned `localStorage`.

Implemented behavior:

- namespaced key `sigs-oglab.project-collection.v1`
- synchronous validated load before first project render
- automatic save after reducer state changes
- empty collection removes the key
- deterministic Flow/test URLs do not load or write user projects
- damaged and unsupported data recover to the project hub with a dismissible notice
- project hub provides confirmed `清除本机项目`

Workspace files, backend/database persistence, migration, and cross-tab conflict handling remain future separate scopes.
