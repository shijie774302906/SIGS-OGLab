# 地层分层 F2 公式/规则候选合同

日期：2026-07-10  
状态：`已实现 / 已验收 / 已独立复查`

## 1. 页面任务

F2 不替代手动分层，也不把规则结果写成已确认地层。页面只增加一条可解释的候选路径：

```text
当前检查结果
-> 选择规则并设置参数
-> 生成不可变候选运行
-> 在曲线中查看候选边界与来源窗口
-> 转为新的可编辑方案
-> 人工移动、增加、删除、合并和补充土类
-> 显式提交为新的分层修订
-> 参数解译继续只消费已提交修订
```

## 2. 首版规则

规则 ID：`qc_fr_change_point_v1`  
用户名称：`qc / Fr 变化点`  
定位：透明的原型候选规则，不是正式工程分层标准。

对每个可能的分割位置，分别取前后 `windowRows` 行中位数：

```text
qc_component = 1 - exp(-abs(ln(qc_below / qc_above)))
fr_component = 1 - exp(-abs(ln(fr_below / fr_above)))
score = 0.7 * qc_component + 0.3 * fr_component
```

当任一行 `Fr` 缺失或非正时，本次运行使用：

```text
score = qc_component
```

同时保留 `StrRuleFrUnavailable` 提示，不得伪装成完整双指标运行。

候选深度是相邻前后窗口之间两行深度的中点。阈值判断使用未舍入评分，12 位小数只用于不可变结果快照和显示；先按原始评分从高到低选择，再执行端点结构间距、候选间最小边界间距和边界数量上限，最终按深度排序显示。同分时深度较浅者优先。

默认设置：

| 设置 | 默认值 | 合法范围 |
| --- | ---: | ---: |
| 前后窗口 | 3 行 | 2-12 行 |
| 变化阈值 | 0.28 | 0.05-0.95 |
| 最小边界间距 | 0.50 m | 0.05-20 m |
| 候选边界上限 | 8 | 1-30 |

## 3. 对象生命周期

### 3.1 候选运行

```text
queued -> running -> completed
                  -> failed
queued/running -> cancel-requested -> cancelled
queued/running/cancel-requested -> invalidated
```

运行冻结：

- 当前点位、草稿、批次、完整修订向量和检查运行。
- 完整、有序的来源行快照，不允许先删行再运行。
- 规则规格、设置、输入、来源和结果哈希。
- 候选边界评分、前后窗口中位数及来源行 ID。
- 问题码、摘要、终态时间和失效原因。

终态运行不可修改或删除。上游变化只使开放运行失效，不删除历史。

### 3.2 候选方案

`completed` 且无问题的运行可以创建一个新方案：

- `origin.kind = rule-candidate` 并引用精确运行。
- 候选边界全部标记为需复核。
- 候选土层默认未分类且需复核。
- 每条候选生成的边界保存结构化 `ruleRunId / candidateId / originalDepthM / sourceRowIds`；移动后仍能追溯原候选，删除或合并后对应引用随边界移除。
- 创建后进入现有编辑会话，可继续手动修改。
- 只有现有“提交编辑”动作才能形成不可变分层修订。

## 4. Feature Coverage Gate

| 用户动作 | 对象 | 正常状态 | 可能事件 | 恢复 |
| --- | --- | --- | --- | --- |
| 选择规则 | 规则规格 | 显示固定公式和变量 | 规则版本不支持 | 切回受支持规则 |
| 调整设置 | 设置草稿 | 范围内可运行 | 窗口、阈值、间距或上限无效 | 修正对应控件 |
| 运行候选 | 规则运行 | 完成并显示候选 | 数据不足、深度逆序、qc 无效 | 返回数据检查 |
| 查看候选 | 候选边界 | 曲线、评分和来源窗口联动 | Fr 缺失、没有候选 | 调整阈值或继续手动 |
| 取消运行 | 规则运行 | 终态 cancelled | 迟到完成 | 取消结果优先，不保留部分结果 |
| 转为方案 | 分层方案 | 新建可编辑方案 | 上游已变化、当前有未提交编辑 | 重跑或先处理当前编辑 |
| 人工修正 | 编辑会话 | 复用拖动、撤销、重做、合并 | 边界过近或范围外 | 页面原位提示并保持上次有效值 |
| 提交方案 | 分层修订 | 新修订成为当前输入 | 检查修订已变化 | 放弃失效编辑并基于最新检查重跑 |

持久化补充约束：当前草稿必须覆盖该点位完整、有序的规范化来源行；所有带 `normalizedDataHash` 的终态检查运行从创建时就进入解译权威摘要，不等待被 F2 首次引用；F2 只能引用状态为 `completed`、结论为“无问题”且 `normalizedDataHash` 与当前数据块一致的检查运行。规则运行、方案、修订和编辑会话继续作为同一权威链的组成。F2 变更必须精确递增 manifest CAS；已提交方案必须与同版本不可变修订的几何、名称、输入和 origin 一致，不允许降级为 `working` 绕过修订链；`working` 只能是无修订的新方案，并由同一 `isNew` 编辑会话承接；删除方案留下 append-only tombstone，修订版本必须从 1 连续递增。

## 5. Event Matrix

```text
Event: 输入不足
Detection: rowCount < 2 * windowRows
User-facing state: 存在问题
Available actions: 返回数据检查；减小窗口
Disabled actions: 转为候选方案
Recovery path: 数据检查或规则设置
Acceptance evidence: StrRuleInputTooShort + 0 candidate
```

```text
Event: 深度重复或逆序
Detection: depth[i] <= depth[i-1]
User-facing state: 存在问题
Available actions: 返回数据检查定位来源行
Disabled actions: 转为候选方案
Recovery path: 数据检查
Acceptance evidence: StrRuleDepthOrderInvalid + sourceRowIds
```

```text
Event: Fr 不完整
Detection: any Fr missing, non-finite, or <= 0
User-facing state: 可运行但保留提示
Available actions: 查看 qc-only 候选；返回检查；手动分层
Disabled actions: 表示为完整 qc/Fr 结果
Recovery path: 数据检查或人工确认
Acceptance evidence: StrRuleFrUnavailable + qc-only oracle
```

```text
Event: 当前阈值没有候选
Detection: selectedBoundaryCount = 0
User-facing state: 无候选，不是数据问题
Available actions: 调整阈值；继续手动分层
Disabled actions: 转为空候选方案
Recovery path: 规则设置或手动分层
Acceptance evidence: StrRuleNoCandidates
```

```text
Event: 阈值命中点距有效深度端点过近
Detection: candidate depth leaves either edge thinner than 0.05 m
User-facing state: 命中点不进入候选并保留提示
Available actions: 手动分层；扩大有效数据范围
Disabled actions: 转为必然失败的候选方案
Recovery path: 手动分层或数据检查
Acceptance evidence: StrRuleCandidateOutsideEditableRange
```

```text
Event: 上游检查变化
Detection: exact input lineage mismatch
User-facing state: 候选已过期
Available actions: 查看历史；按最新检查重跑
Disabled actions: 转为当前方案
Recovery path: 最新数据检查 -> 新规则运行
Acceptance evidence: open run invalidated; completed history retained
```

## 6. 页面承接

- 左侧：固定五区工作流，不新增导航页。
- 中心：qc 曲线、候选边界、当前方案边界和土层表；候选与当前边界使用不同线型。
- 右侧：`手动编辑 / 规则候选` 分段模式；规则模式承接设置、运行、问题、候选列表和“转为可编辑方案”。
- 候选不得使用成功色；只有已提交方案才能显示为当前工作输入。

视觉计划：

- 规则候选使用 `#35b0f5` 蓝色虚线，已选候选使用 `#bdadff` 紫色强调。
- 已提交/可继续状态使用 `#2abf9a`，问题使用 `#fe92a1`。
- 保持现有紧凑分析工作台字体与 8px 以下圆角，不新增卡片套卡片。

## 7. 验收

1. 独立数值 oracle 验证明确阶跃数据的唯一边界和评分。
2. 领域测试覆盖正常、Fr 缺失、无候选、输入不足、逆序、取消、迟到完成、失效和人工修正。
3. 持久化拒绝漏行、伪造评分、伪造来源、终态改写和删除运行。
4. Playwright 生成随机 CSV，经真实上传、检查、规则运行、候选预览、转为方案、人工移动和提交走完整人类 flow。
5. 保存 `1440x900` 与 `1920x1080` 截图、`flow-run.json`、输入 CSV、console/page error 和布局检查。
6. 三个只读复查轨道最终均为 `P0=0 / P1=0`。
