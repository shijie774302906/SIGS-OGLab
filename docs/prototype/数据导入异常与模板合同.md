# 数据导入异常与模板合同

Date: 2026-07-09

Status: `active general exception and template contract`

Scope:

- 当前文档先作为功能设计合同保存。
- 不代表已经实现全部异常处理。
- 不代表正式导入、正式保存、数据库写入或生产解析能力已经开放。
- 字段映射、单位确认、真实点位集合和多点拆分的详细对象模型，以 `数据导入映射单位与多点合同.md` 为执行基线；本文件继续维护异常分类、模板和通用 Feature Coverage Gate。

## 1. 目的

这个文档解决两个问题：

1. 数据导入本身会遇到哪些异常，页面应该如何承接。
2. 后续建立任何新功能时，如何系统性地把“可能发生的事件”和“需要补的功能模块”考虑进去，而不是依赖用户临时想全。

核心方法：

```text
用户动作 -> 对象生命周期 -> 可能事件 -> 状态变化 -> 页面承接 -> 功能补齐 -> 验收用例
```

## 2. 数据导入用户动作链

```text
进入数据导入
-> 选择模板或上传文件
-> 生成导入草稿
-> 解析文件结构
-> 识别点位归属
-> 推断字段映射
-> 识别单位
-> 预览原始/标准化数据
-> 预检字段、单位、深度、数值范围
-> 用户修正或确认
-> 用于数据检查
```

每个动作都必须回答：

| 问题 | 说明 |
| --- | --- |
| 用户想完成什么？ | 例如上传 CPTU 数据，确认能进入检查。 |
| 系统创建或更新什么对象？ | 例如导入草稿、字段映射、预检问题。 |
| 可能失败在哪里？ | 文件、字段、单位、点位、行数据、深度、状态。 |
| 用户能如何恢复？ | 重新上传、改映射、选单位、下载模板、返回修改。 |
| 页面如何证明状态？ | 表格、提示、定位、右侧 dock、toast、flow-run JSON。 |

## 3. 导入对象生命周期

| Object | Created By | Updated By | Consumed By | States |
| --- | --- | --- | --- | --- |
| 导入来源 | 选择文件 / 拖入文件 / 模板下载 | 重新选择 / 替换 | 导入草稿 | 未选择 / 已选择 / 不支持 / 需解析器 |
| 导入草稿 | 解析 CSV / Excel 解析器 | 清空 / 替换 / 返回修改 | 字段映射、数据检查 | 待解析 / 可预览 / 存在问题 / 可检查 |
| 字段映射 | 自动推断 / 模板匹配 | 手动修改 / 重置 | 标准化预览、预检 | 待确认 / 已确认 / 存在问题 / 仅提示 |
| 单位契约 | 表头识别 / 用户选择 | 单位换算策略 | 数值标准化、检查规则 | 待确认 / 已确认 / 需复核 |
| 点位归属 | 文件字段 / 当前点位 | 用户选择归属策略 | 项目/点位数据、数据检查 | 匹配当前点位 / 不一致 / 新点位 / 多点位 |
| 原始预览 | 文件解析 | 重新上传 | 用户核对 | 可读 / 空文件 / 乱码 / 行列异常 |
| 标准化预览 | 映射 + 单位 | 映射修改 / 单位修改 | 数据检查 | 可检查 / 存在问题 / 仅提示 |
| 导入问题 | 预检规则 | 用户修正后重算 | 右侧 dock、数据检查 | 存在问题 / 仅提示 / 已处理 |

## 4. 模板合同

模板不是一个“下载文件”按钮，而是一组降低出错率的入口。

| Template Action | Purpose | UI Surface | Expected Result |
| --- | --- | --- | --- |
| 下载空模板 | 给用户标准字段结构 | 数据导入上传区 / 右侧 dock | 空 CSV/XLSX 模板 |
| 下载示例模板 | 让用户看真实格式和单位 | 数据导入上传区 / 帮助 popover | 带 3-5 行示例数据 |
| 复制标准表头 | 用户自己在 Excel 中粘贴 | 字段说明 popover | 表头复制到剪贴板 |
| 查看字段说明 | 解释字段含义和单位 | 右侧 dock / 弹窗 | 字段字典 |
| 下载异常示例 | 用于开发和验收 | 开发/测试入口，不默认给普通用户 | 缺字段、错单位、深度倒序等样例 |

### 4.1 推荐模板字段

必需字段：

| Field | Meaning | Unit | Required | Notes |
| --- | --- | --- | --- | --- |
| `PointName` | 点位编号 | text | yes | 用于绑定当前点位或创建新点位草稿 |
| `DepthM` | 深度 | m | yes | 必须数值、向下递增 |
| `QcKpa` 或 `Qc` | 锥尖阻力 qc | kPa 或 MPa | yes | 如果单位不明，需要用户确认 |
| `QtKpa` 或 `Qt` | 修正锥尖阻力 qt | kPa 或 MPa | recommended | 缺失时需标记后续影响 |
| `FsKpa` 或 `Fs` | 侧阻 fs | kPa | recommended | 可用于 Fr 派生或检查 |
| `U2Kpa` 或 `U2` | 孔压 u2 | kPa | recommended | CPTU 场景建议必填 |
| `FrPercent` 或 `Fr` | 摩阻比 | % | recommended | 可由 Fs/Qt 候选派生，但必须标记需复核 |
| `WaterDepthM` | 水深 | m | recommended | 来源需复核 |
| `FinalDepthM` | 最终孔深 | m | yes | 用于深度范围检查 |

可选字段：

| Field | Meaning | Notes |
| --- | --- | --- |
| `X` / `Y` | 平面坐标 | 后续点位位置或二维/三维场景使用 |
| `Date` | 测试日期 | 可用于追溯 |
| `SourceFile` | 来源文件名 | 批量导入时有用 |
| `Remark` | 备注 | 不参与计算 |

### 4.2 模板生成规则

模板必须包含：

- 表头。
- 单位说明。
- 示例行。
- 必需/建议/可选字段标记。
- 字段别名说明。
- 不能继续的条件说明。

模板不应包含：

- 正式公式承诺。
- 数据库写入承诺。
- 成果导出承诺。
- 内部路径或开发日志。

## 5. 数据导入异常矩阵

| Category | Event | Detection | User-Facing State | Required Function | Recovery Action | Acceptance Evidence |
| --- | --- | --- | --- | --- | --- | --- |
| 文件类型 | 上传非 CSV/Excel | 扩展名或 MIME 不支持 | 存在问题 | 文件类型检查 | 重新选择文件 / 下载模板 | 上传 `.txt` 后不可继续 |
| 文件类型 | Excel 已选择但无解析器 | `.xlsx` 且当前未接解析器 | 需处理 | Excel 待解析状态 | 改用 CSV / 后续解析器 | UI 不显示解析成功 |
| 文件内容 | 空文件 | 无表头或无数据行 | 存在问题 | 空文件检查 | 重新上传 | 问题行显示空文件 |
| 文件内容 | 乱码或编码异常 | 表头不可读 / 大量非法字符 | 存在问题 | 编码提示 | 选择编码 / 重新导出 | 显示可读性问题 |
| 文件结构 | 多 sheet | Excel 解析器发现多个 sheet | 需选择 | sheet 选择器 | 选择 sheet | 选择后刷新预览 |
| 文件结构 | 表头不在第一行 | 前几行无法匹配字段 | 存在问题 | 表头行选择 | 选择表头行 | 映射重新计算 |
| 点位归属 | 文件点位与当前点位不一致 | `PointName != currentPoint` | 存在问题 / 需确认 | 点位归属决策 | 新建点位 / 替换当前 / 取消 | 选择分支写入 flow-run |
| 点位归属 | 一个文件多个点位 | 多个 `PointName` | 需确认 | 多点位拆分 | 分点位导入 / 只导当前点位 | 生成多个草稿或筛选 |
| 重复导入 | 当前点位已有草稿 | same point + existing draft | 需确认 | 草稿替换确认 | 替换 / 保留并新建 / 取消 | 弹窗或右侧确认 |
| 字段映射 | 缺 `DepthM` | 必需字段无匹配 | 存在问题 | 缺字段检测 | 手动映射 / 下载模板 | `用于数据检查` 禁用 |
| 字段映射 | 缺 `FinalDepthM` | 必需字段无匹配 | 存在问题 | 缺字段检测 | 手动映射 / 补字段 | 深度范围检查不可继续 |
| 字段映射 | 缺 `Qt` 但有 `Qc` | 建议字段缺失 | 仅提示 / 需复核 | 字段影响说明 | 继续但记录影响 | 检查页保留提示 |
| 字段映射 | 字段歧义 | 多个候选匹配同一目标 | 需确认 | 映射候选面板 | 用户选择候选 | 选择后刷新预览 |
| 字段映射 | 重复映射 | 两个目标指向同一源字段 | 存在问题 | 映射冲突检测 | 改映射 / 重置 | 冲突字段高亮 |
| 单位 | kPa/MPa 不明 | 表头无单位且值域异常 | 需复核 | 单位选择 | 选择 kPa/MPa | 单位策略写入结果 |
| 单位 | Fr 为小数或百分比不明 | Fr 值域 0-1 或 0-100 | 需复核 | Fr 单位判断 | 选择 `%` 或小数 | 预览换算说明 |
| 数值 | 非数字 | 单元格无法转 number | 存在问题 | 单元格解析检查 | 定位行列 / 修改文件 | 高亮行号和字段 |
| 数值 | 空值过多 | 缺失率超过阈值 | 存在问题 / 仅提示 | 缺失率检查 | 返回导入 / 继续记录 | 问题列表显示比例 |
| 深度 | 深度不递增 | `DepthM[n] <= DepthM[n-1]` | 存在问题 | 深度递增检查 | 定位行 / 修正文件 | 行号、深度范围 |
| 深度 | 深度超过最终孔深 | `maxDepth > FinalDepthM` | 存在问题 | 深度范围检查 | 修正 FinalDepthM 或数据行 | 不能进入检查通过 |
| 深度 | 最终孔深缺失 | `FinalDepthM` missing | 存在问题 | 孔深字段检查 | 补字段 / 手动输入 | 检查页显示影响 |
| 操作 | 用户清空草稿 | 点击清空 | 需确认 | 清空确认 | 清空 / 取消 | 草稿状态重置 |
| 操作 | 用户重新上传 | 选择新文件 | 需确认 | 替换草稿 | 替换 / 保留 | 新旧文件清晰显示 |
| 流程 | 检查后又修改导入 | 导入草稿版本变更 | 需重新检查 | 检查失效标记 | 重新检查 | 检查按钮重新启用 |

## 6. 页面承接规则

### 6.1 Center Surface

中间区域优先展示“当前证据”：

- 上传区和导入草稿。
- 字段映射表。
- 原始表头预览。
- 标准化数据预览。
- 问题行/字段/深度定位。

中间区域不应该变成：

- 长说明页。
- 内部日志页。
- 只有状态没有操作的展示页。

### 6.2 Right Functional Dock

右侧功能坞放当前页动作：

| Page | Dock Actions |
| --- | --- |
| 项目/点位数据 | 筛选点位、确认当前点位、进入导入 |
| 数据导入 | 选择批次、选择字段、确认单位、下载模板、清空草稿、用于数据检查 |
| 数据检查 | 筛选规则、定位问题、返回导入、进入地层分层 |

右侧不重复中间表格，不做第二个左侧导航。

### 6.3 Popover / Dialog

短任务用 popover：

- 字段候选选择。
- 单位选择。
- 规则筛选。
- 模板下载选项。

破坏性或分支选择用 dialog：

- 清空草稿。
- 替换已有草稿。
- 点位不一致时选择归属。
- 多点位文件拆分策略。

## 7. 通用功能建立工作流

这个部分不只适用于数据导入。以后建立任何功能，都按这个方法走。

### Step 1: 用户动作清单

先写用户会做什么，而不是页面上放什么。

格式：

```text
Action:
Intent:
Entry:
Object changed:
Next handoff:
```

例子：

```text
Action: 上传 CSV
Intent: 把外部 CPTU 数据转成可检查草稿
Entry: 数据导入上传区
Object changed: 导入来源、导入草稿、字段映射、预览行
Next handoff: 数据检查
```

### Step 2: 对象生命周期

每个功能都必须明确它创建、读取、更新、消费什么对象。

格式：

```text
Object:
Created in:
Updated by:
Consumed by:
States:
Invalid states:
```

如果说不清对象，就不要开始实现。

### Step 3: 事件枚举

用六类事件防漏：

| Event Type | Questions |
| --- | --- |
| 用户主动事件 | 用户点击、上传、选择、取消、返回、重试了吗？ |
| 系统解析事件 | 系统读文件、跑检查、生成预览、推断字段了吗？ |
| 数据异常事件 | 缺字段、错单位、空值、重复、范围异常了吗？ |
| 状态失效事件 | 上一步修改导致下一步结果失效了吗？ |
| 分支决策事件 | 用户需要选择策略吗？例如替换/新建/取消。 |
| 恢复事件 | 用户能从问题返回到正确位置修改吗？ |

### Step 4: 状态矩阵

每个对象至少要有：

```text
未开始
进行中
可继续
仅提示
存在问题
已确认
已失效
```

不是每个状态都要显示，但每个状态都要知道页面怎么处理。

### Step 5: 异常矩阵

每个功能必须写异常矩阵：

```text
Event:
Detection:
User-facing state:
Message:
Available actions:
Disabled actions:
Evidence:
Playwright case:
```

没有异常矩阵的功能，默认视为未设计完整。

### Step 6: 功能补齐表

把事件倒推成功能。

| Event | Missing Function | UI Surface | Data Needed | Test Needed |
| --- | --- | --- | --- | --- |
| 缺必需字段 | 字段缺失检测 | 映射表 / 右侧 dock | headers | bad CSV upload |
| 点位不一致 | 点位归属选择 | dialog / right dock | currentPoint + filePoint | mismatch CSV |
| 修改导入后检查失效 | 检查失效标记 | header / check page | draftVersion + checkRunVersion | upload after check |

### Step 7: 验收反推

每个功能不算完成，除非能用人类 flow 证明。

验收必须包含：

- 正常路径。
- 至少一个错误路径。
- 至少一个恢复路径。
- 截图。
- 机器可读证据。
- console/page error。
- overflow 检查。

### Step 8: 文案边界

功能还没生产化时，避免使用：

- 正式保存。
- 正式导入。
- 已采纳。
- 最终成果。
- 自动修复。

推荐使用：

- 导入草稿。
- 用于数据检查。
- 映射待确认。
- 仅提示。
- 返回导入修改。
- 当前预览结果。

## 8. Feature Coverage Gate

以后任何功能开工前，都必须先通过这个 gate。它的作用是防止只做正常路径，或把验收脚本误当成功能设计。

Gate 顺序：

```text
用户动作 -> 对象生命周期 -> 可能事件 -> 状态变化 -> 页面承接 -> 功能补齐 -> 验收用例
```

### 8.1 必答问题

| Question | Required Answer |
| --- | --- |
| 用户会做哪些动作？ | 点击、上传、选择、取消、返回、重试、修改、继续。 |
| 每个动作改变什么对象？ | 创建、读取、更新、消费的对象必须明确。 |
| 正常路径怎么走？ | 用户从开始到完成的主路径。 |
| 错误路径怎么走？ | 文件、字段、单位、点位、数据行、状态失效等异常。 |
| 取消路径怎么走？ | 用户取消上传、取消替换、取消分支选择后的状态。 |
| 返回路径怎么走？ | 从问题回到正确字段、行、配置或页面。 |
| 重试路径怎么走？ | 重新上传、重新映射、重新检查。 |
| 状态失效怎么处理？ | 上游修改后，下游结果必须标记失效或要求重新运行。 |
| 哪些状态禁止继续？ | `存在问题`、解析失败、缺必需字段、检查失效等。 |
| 哪些状态允许继续但要提示？ | `仅提示`、建议字段缺失、来源需复核等。 |
| 需要补哪些功能？ | UI 控件、接口、状态、模板、弹窗、右侧 dock、数据对象。 |
| Playwright 如何证明？ | 生成输入、模拟人类操作、截图、JSON 证据、错误检查。 |

### 8.2 Event Matrix 模板

每个实质性功能必须写事件矩阵：

| Event | Detection | User-facing State | Available Actions | Disabled Actions | Recovery Path | Acceptance Evidence |
| --- | --- | --- | --- | --- | --- | --- |
| 例：缺 DepthM | 表头无深度字段 | 存在问题 | 手动映射 / 下载模板 / 重新上传 | 用于数据检查 | 返回字段映射 | bad CSV + 截图 + flow-run |

字段定义：

- `Event`: 发生了什么。
- `Detection`: 系统如何发现。
- `User-facing State`: 用户看到的状态词。
- `Available Actions`: 用户当前还能做什么。
- `Disabled Actions`: 当前必须禁用什么。
- `Recovery Path`: 用户如何回到正确位置修改。
- `Acceptance Evidence`: 如何用人类 flow 证明。

### 8.3 功能补齐表模板

事件矩阵完成后，再倒推功能补齐表：

| Event | Missing Function | UI Surface | Data Needed | Test Needed |
| --- | --- | --- | --- | --- |
| 缺必需字段 | 字段缺失检测 | 映射表 / 右侧 dock | headers | missing-depth.csv |
| 点位不一致 | 点位归属选择 | dialog / right dock | currentPoint + filePoint | point-mismatch.csv |
| 修改导入后检查失效 | 检查失效标记 | header / check page | draftVersion + checkRunVersion | upload-after-check |

### 8.4 开工条件

一个功能可以开始实现，必须满足：

- 用户动作清单已写。
- 对象生命周期已写。
- Event Matrix 已写。
- 功能补齐表已写。
- 页面承接位置已明确。
- 数据来源已明确。
- Playwright 验收路径已明确。
- 非目标已明确。

如果缺其中任意一项，先补设计，不进入实现。

## 9. 后续实现优先级

建议下一批先做：

| Priority | Feature | Reason |
| --- | --- | --- |
| P0 | 模板入口 | 用户不知道正确格式时必须有标准路径 |
| P0 | 缺必需字段 | 最常见且会直接影响检查 |
| P0 | 深度不递增 | CPT/CPTU 数据核心质量问题 |
| P0 | 点位不一致 | 防止导错点位 |
| P1 | 单位确认 | kPa/MPa/%/小数容易误判 |
| P1 | 清空/替换草稿 | 避免重复导入和状态混乱 |
| P1 | 检查失效状态 | 导入修改后旧检查不能继续当新结果 |
| P2 | Excel 解析器决策 | 需要依赖选择和多 sheet 策略 |
| P2 | 多点位批量导入 | 重要但会扩大状态复杂度 |

## 10. Playwright 场景库建议

建议建立一组生成器：

| Generator | Purpose |
| --- | --- |

## 12. 当前数据导入事件合同 - 可执行版

本节把前面的设计收敛成当前切片可执行的合同。后续实现、测试和复查都必须按事件 ID 对齐，避免只覆盖正常路径。

### 12.1 合同边界

本合同覆盖：

- CSV 上传、模板入口、字段识别、点位归属、深度预检、导入后检查联动。
- Excel 只显示“已选择但需要后续解析器”，不进入正式解析。
- 所有结果都是浏览器原型状态，不写入数据库，不承诺正式导入。

本合同不覆盖：

- 生产级 Excel 多 sheet 解析。
- 正式保存、正式入库、正式成果导出。
- 官方公式、工程最终判定或桌面端同步。

## 14. 分步执行清单

### Step A: 模板入口

目标：

- 用户在不知道格式时，可以获得标准入口。
- 模板入口不承诺正式导入，只用于原型预览和上传准备。

需要实现：

- `下载空模板`
- `下载示例模板`
- `复制标准表头`
- 字段字典入口或简表

验收：

- Playwright 能看到模板按钮。
- 至少一个模板下载动作触发浏览器 download。
- 标准表头与字段映射表一致。

### Step B: 文件选择与解析状态

目标：

- 文件被选择后，页面明确显示它处于哪种状态。

需要实现：

- CSV 可解析状态。
- Excel 待解析状态。
- 不支持文件状态。
- 空文件状态。

验收：

- `.xlsx` 不显示解析成功。
- `.txt` 和空 CSV 禁用 `用于数据检查`。
- 每个状态都有恢复动作。

### Step C: 字段问题

目标：

- 必需字段缺失不再只是 parse error，而是可见的问题清单。

需要实现：

- 保留原始 headers 和 raw preview。
- 必需字段缺失列表。
- 建议字段缺失提示。
- `用于数据检查` 禁用条件。

验收：

- 缺 `DepthM` 时，字段映射表显示未匹配。
- 右侧 dock 给出模板/重新上传动作。
- Playwright 证明无法继续检查。

### Step D: 点位归属

目标：

- 防止用户把 A 点位文件导入 B 点位。

需要实现：

- 当前点位与文件点位比对。
- 点位不一致时出现策略选择。
- 用户选择后写入草稿状态。

验收：

- mismatch 文件上传后不可直接检查。
- 选择 `作为新点位草稿` 后，草稿变成可检查或仅提示。
- 取消导入后回到待选择或上一个草稿。

### Step E: 数值、深度、单位预检

目标：

- 进入数据检查之前，先拦截会破坏基本数据可信度的问题。

需要实现：

- 非数字定位。
- 深度不递增定位。
- 深度超过最终孔深定位。
- 单位不明确提示和后续选择预留。

验收：

- 深度不递增 case 显示行号和相邻深度。
- 深度超过最终孔深 case 显示最大深度与最终孔深。
- 所有 P0 问题禁用 `用于数据检查`。

### Step F: 检查失效联动

目标：

- 导入修改后，旧检查结果不能继续被当成新结果。

需要实现：

- `draftVersion`
- `checkVersion`
- 重新上传或字段变更后标记 `需重新检查`
- 重新检查后恢复后续流转。

验收：

- 先跑检查，再上传新 CSV，数据检查页显示需重新检查。
- `进入地层分层` 禁用，直到重新运行数据检查。

### Step G: 验收证据库

目标：

- 用户不需要信任自检描述，而是可以看见每条异常的人类 flow 证据。

需要实现：

- 随机 CSV generator。
- 每个 case 的 input 文件。
- 截图。
- `flow-run.json`。
- console/page error 记录。

验收：

- `npm run test:e2e` 覆盖正常路径、错误路径、恢复路径。
- process log 记录每个 case 的路径和结果。
