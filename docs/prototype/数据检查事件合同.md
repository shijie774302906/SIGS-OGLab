# 数据检查事件合同

Date: 2026-07-10

Status: `active contract / implemented baseline`

## 1. Purpose

`数据检查` 是进入 `地层分层` 前的数据质量门和问题处置工作台，不是只读报告页。

它回答：

```text
当前导入草稿是否已经检查？
检查结论对应哪一版导入草稿？
是否存在问题？
哪些只是提示？
问题定位到哪个字段、深度、行号和证据值？
用户应该回哪里修？
修完后如何重新检查？
是否可进入地层分层？
```

## 2. Scope

当前合同覆盖：

- 检查运行。
- 检查状态。
- 检查规则组。
- 问题/提示/通过筛选。
- 选中问题证据定位。
- 返回数据导入修复。
- 导入变更后的 `需重新检查`。
- 检查记录。
- 进入 `地层分层` 门禁。

不覆盖：

- 官方公式。
- 生产级工程判定。
- 正式保存检查报告。
- PDF/DXF/Excel 成果输出。
- 后端或数据库持久化。

## 4. User Actions

| Action | Intent | Object Changed | Next Handoff |
| --- | --- | --- | --- |
| 打开数据检查 | 查看检查状态 | none | 未检查 / 已检查 / 需重新检查 |
| 运行数据检查 | 生成检查运行 | CheckRun + CheckIssues | 检查结论 |
| 筛选规则 | 聚焦问题类型 | selectedCheckFilter | 问题表 |
| 选择问题 | 查看证据和建议 | selectedCheckIssue | IssueEvidence |
| 返回数据导入 | 修复字段或文件 | activeRoute/importFocus | 数据导入 |
| 重新检查 | 修复后生成新运行 | CheckRun | 新检查结论 |
| 进入地层分层 | 通过质量门 | activeRoute | 地层分层 |

## 5. Event Matrix

| ID | Event | Detection | User-facing State | Available Actions | Disabled Actions | Recovery Path | Acceptance Evidence |
| --- | --- | --- | --- | --- | --- | --- | --- |
| CHK-E01 | 未运行检查 | `checkedDraftVersion === null` | 未检查 | 运行数据检查 / 返回导入 | 进入地层分层 | 运行检查 | open-check-before-run case |
| CHK-E02 | 导入草稿不可检查 | `!isImportDraftCheckable` | 存在问题 | 返回数据导入 | 运行检查 / 进入地层分层 | 修复导入 | bad import -> check case |
| CHK-E03 | 检查运行成功 | valid draft + run | 已检查 | 筛选规则 / 选择问题 / 进入分层 | none if no issue | none | normal check case |
| CHK-E04 | 检查仅有提示 | blocking count = 0, warning > 0 | 仅提示 / 可进入地层分层 | 查看提示 / 进入分层 / 返回导入 | none | 可保留提示 | warning filter case |
| CHK-E05 | 检查存在问题 | blocking count > 0 | 存在问题 | 选择问题 / 返回导入 / 重新检查 | 进入地层分层 | 修复并重新检查 | issue filter case |
| CHK-E06 | 选择问题 | click issue row | 问题定位 | 查看证据 / 返回导入 | none | 定位字段或行 | selected issue screenshot |
| CHK-E07 | 检查后导入变更 | draft version != checked version | 需重新检查 | 重新检查 / 返回导入 | 进入地层分层 | 重新运行检查 | stale check case |
| CHK-E08 | 筛选问题 | click status/rule filter | 已筛选 | 切换筛选 / 选择问题 | none | 全部规则 | filter evidence |
| CHK-E09 | 返回导入修复 | click return | 返回导入修改 | 重新上传 / 定位字段 | 进入旧检查 | 修复后重新检查 | return-to-import case |
| CHK-E10 | 进入分层 | no blocking + current check | 可进入地层分层 | 进入地层分层 | none | none | continue case |
| CHK-E11 | qc 存在零值或负值 | parsed row has `qcKpa <= 0` | 存在问题 | 查看证据 / 返回数据导入 | 进入地层分层 | 定位 `QcKpa`、上传修正文件、重新检查 | generated CSV recovery flow |

- 进入地层分层。

## 7. Required Rule Groups

当前原型规则组：

- 必需字段。
- 点位归属。
- 深度递增。
- 最终孔深范围。
- 数值有效性。
- qc 正值检查。
- 单位契约。
- 水深来源。
- Fr 范围提示。
- 进入地层分层判断。

注意：当前原型只做质量门和预览判断，不做官方公式或生产级工程结论。

## 8. Implementation Steps

1. 新增检查运行记录和筛选状态。
2. 增加未检查状态。
3. 增加检查范围和检查记录。
4. 将规则组从静态标签改为可筛选控件。
5. 增加证据行表。
6. 增加右侧重新检查动作。
7. 补 Playwright 覆盖未检查、筛选、提示、问题、失效和恢复。

## 9. Acceptance

Playwright must prove:

- 直接打开数据检查时显示 `未检查`，不能进入地层分层。
- 运行检查后显示检查记录和检查范围。
- 可筛选 `存在问题` / `仅提示` / `通过`。
- 选择提示时显示字段、深度、行号、证据行。
- 导入变更后显示 `需重新检查`，禁止进入地层分层。
- 重新检查后恢复 `可进入地层分层`。
- 上传结构合法但 qc 含负值的 CSV 后，导入草稿仍可检查；检查运行产生 CHK-E11、定位 `QcKpa` 和具体行，并禁止进入地层分层。
- 返回导入上传修正文件并重新检查后，恢复 `可进入地层分层`。
- 返回导入能定位字段。
- console/page errors 为空。
