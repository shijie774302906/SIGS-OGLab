# Memory

This file records only confirmed recurring mistakes and durable user preferences. Stable operating rules belong in `AGENTS.md`; product scope belongs in `plan-total.md`; task history belongs in `process_logs/`.

## Confirmed Lessons

- Chinese Markdown is UTF-8. On Windows PowerShell, use `Get-Content -Encoding UTF8`; default decoding can display valid files as mojibake and make reviews unreliable.
- User-facing terminology uses `问题`, `无问题`, and `存在问题`, not `阻塞`. Use `地层分层`; `测试解译` is legacy/reference wording only.
- The agreed UI palette is `#35b0f5`, `#2abf9a`, `#beae58`, `#fe92a1`, and `#bdadff`. Lavender is the primary UI color, blue is the selection/data accent, teal is success, rose is problem/attention, and olive is reserved until a clear semantic role exists.
- Users need a visible first decision hierarchy. A page should first answer the current object, current state, impact, and next action before presenting metrics and detail.
- Keep exactly one strongest primary action in the center page decision area. Do not repeat it with equal weight in the header or right dock.
- The right side is a page-specific functional dock for tools and choices, default open and collapsible. It is not a generic status detector.
- Avoid repeated filler such as generic `下一步`, `当前项目`, and `后续条件`. Each panel must own a distinct job.
- Keep confirmed, candidate, calculated, and read-only states semantically distinct, but do not add filler labels such as `已试算`, `仅支持原型预览`, `可进入成果预览`, or `可作为预览引用`. Prototype copy must not imply formal adoption, official calculation authority, or formal export.
- Playwright acceptance must exercise human operations with generated upload files when import behavior is under test. Self-check-only assertions are insufficient.
- A downstream artifact must bind both the source object ID and its exact immutable revision ID. Matching only the container ID is insufficient after the source object is revised.
- Automatic stratification candidates must obey the editor's own endpoint and minimum-spacing constraints before conversion. Always run at least one full-scale, high-frequency real dataset; small vectors will not expose dense adjacent-boundary failures.
- A silt drainage decision does not authorize extending a JTS cohesive or sand correlation. If the applicable JTS package has no verified formula, require an explicit manual value and frozen provenance, and keep it visibly separate from JTS calculated results.
- Domain errors shown in a workflow page must name the reason, consequence, affected evidence, owning page, and next action. A raw calculation message without a recovery path is not a complete product state.
- In-place automatic recovery is allowed only when it is deterministic, bounded, previewed, reversible, and append-only. It must preserve raw data, show the revision impact before execution, and keep engineering context decisions manual.
- Engineering exceptions should default to a few plain-language choices with reasons and one recommended action. Treat the first-time user as needing guided operation; keep row evidence, thresholds, and manual control available through collapsed advanced sections.
- Multi-parameter engineering workflows should use an Attio-style guided list: system-preselected items, one parameter at a time, fixed choices, batch application by soil class, explicit exception handling, and advanced controls outside the default path.
- A classification rerun updates classification evidence, not an existing stratification scheme. The UI must say the current scheme is unchanged and require an explicit create-candidate action before scheme content changes.
- Ignoring engineering anomalies must preserve raw measurements and be scoped to one candidate revision. Bound it by physical interval impact, keep provenance and review notices, and never present ignore as deletion or repair.
- A completed calculation state is not proof that the user can inspect the result. For every chart/result slice, Playwright and screenshot review must assert the actual visible artifact (curve path or canvas marks, selector state, units, representative values, empty/disabled states, and cross-page handoff), not only completion text, counts, or stored values.
- Engineering notices and engineering problems must drive different interaction costs. Preserve ordinary boundary/path differences as visible notices, but do not force repetitive per-layer confirmation unless evidence is unclassifiable, explicitly problematic, inherited, or deliberately marked for review.
- A guided workflow's final generation action must remain unique across every exit path. Dirty-state navigation may lead to the final preview, but must never expose a parallel commit button or let tests/fixtures bypass required human confirmation.
- Browser persistence failures must preserve the current in-memory edit, retain the real storage reason, and offer one reason-specific recovery action. Never collapse quota, availability, multi-tab conflict, invalid state, and transient writes into a generic “check space or permissions” message.
- Presentation-only placeholders must never cross into persisted engineering identity. A successful route, row count, or check record does not prove semantic validity; acceptance must assert the real project/point identity and verify that a failed atomic handoff leaves no partial objects.
- A destructive “clear all local data” action must delete the authority database and related boot/legacy pointers, not merely save an empty project list while leaving orphaned measurement and revision blocks. Browser-local persistence cannot provide cross-device or shared-project authority; shared access requires a server-side repository.
- A guided method test must cover the first run on the full real dataset, including the visible running state and double-click protection. Pre-running the method before opening the guide can hide the exact “clicked but nothing happened” failure a user sees.
- For a bounded isolated invalid CPT/CPTU row, prefer a traceable row-scoped ignore over whole-profile smoothing. Preserve the raw row, state the affected percentage, keep all other rows unsmoothed, and resume the user's original candidate-generation task after governance and recheck.
- Stratification review should keep the full qc/fs/u2 profile and layer column as the persistent work surface. Put the selected layer's decision beside the drawing, advance to the next unresolved layer after each fixed choice, and keep structural edits and row-level classification evidence collapsed; do not duplicate the same decision in a standalone JTS panel, long problem list, or per-layer modal.
- Parameter applicability follows the engineer-confirmed final layer class. Row-level JTS classes remain immutable audit evidence and visible conflict counts, but must not silently override the final layer decision.
- Large immutable classification runs must not be cloned during layer selection or acceptance. Clone only mutable stratification state and paint the visible decision before persistence work. Every engineering edit must enter the durability queue immediately; performance optimization may coalesce lower-level writes only when refresh/close cannot lose the latest decision.
- A UI that looks committed is not proof that IndexedDB authority is durable. Cross-page and refresh acceptance must wait for both the visible current state and the persisted current revision; in-flight generation/save actions need a disabled running state to prevent duplicate clicks and stale navigation guards.
- Permanent removal of a CPT/CPTU point must remove the complete row only from current working/downstream input, never erase uploaded evidence, require a reasoned audit record, and remain recoverable only by re-importing the source file. Bulk removal is allowed only for exact same-reason sparse groups with explicit count/range preview and a conservative ratio/non-adjacency gate.
- High-count guided review must use bounded numeric pagination or a compact progress count, not one DOM marker per issue. Destructive batches and final commits must be atomic, cancel-safe, and verified against both visible state and IndexedDB authority.
- Equal chart containers are not proof of a shared engineering depth axis. Curves, selected bands, boundaries, depth ticks and layer blocks must consume the same explicit depth range; acceptance must compare a representative layer's mapped pixel boundaries, not only the outer top and bottom.
- A persisted source selection describes the immutable generation event, while the current stratification scheme remains editable. Validate frozen candidate references and source rows directly; never require the old selected-candidate count to equal the current boundary count after manual edits.
- Controlled engineering editors need optimistic local state plus serialized persistence. While a save is pending or an edit is dirty, an older persisted snapshot must never overwrite the latest input; rapid-input and reload tests must prove the final value survives.
- Closure evidence must bind the archived context, implementation inputs, related tests, curated artifacts, successful verification commands and environment through deterministic hashes. Historical knowledge reports retain their closure-time library hash; later library growth is valid, but changed archived context or evidence is not.
- For non-trivial solution choices, present multiple bounded candidates and use three independent judges to score them against engineering semantics, interaction clarity, maintainability, testability/traceability, and delivery risk. Select the highest total only when no judge triggers a safety or scope veto; retain the scores and rationale with the Process evidence.
- 数据导入与 AI 整理的回归测试默认使用固定随机种子的生成 CSV/Excel，不要求用户提供真实工程文件；只有无法复现专有文件结构时，才请求最小脱敏样本。
- 思考模型的连接验证成功不代表多轮工具调用可用。必须保留提供方要求的受限协议字段、按任务设置足够输出预算，并根据 `finish_reason` 区分截断、协议问题和真实服务故障；不要把它们统一显示为连接失败。
